你陆续尝试：

| 尝试 | 现象 |
|------|------|
| TIM8 第二路电机 + 固定 Uq（非 VF 开环） | 加 `setPhaseVoltage` 后 VOFA 停 |

**关键二分实验（不连电机，逐项注释 `setPhaseVoltage` 内函数）：**

| 配置 | `isr_delta`（约） | VOFA |
|------|-------------------|------|

| 去掉 atan2 | 6625 | 不行 |
| 再去掉 nor（`fmod`） | **5801** | 不行 |
| 再去掉 sqrt | **2719** | **可以** |
| 再去掉遥测 | 2660 | — |

**遥测自身仅 ~59 cycle/拍（可忽略）。**

### 阶段 6：Watch 可观测变量 + nor 开/关对比（今晚）

扩展 `g_telem_dbg`：任务循环、DMA 计数、缓冲状态、`acquire_fail` 等。

| 状态 | `isr_delta` | `uart_task_loops` | `dma_start_ok` | `acquire_fail` |
|------|-------------|-------------------|----------------|----------------|
| **nor 开** | ~3700~5800 | **0** | **0** | **3432** |
| **nor 关** | **~2707** | **50312** | **98** | **0** |

**因果链（你已用实验证实，非混合故障）：**

```
nor(fmod 双精度) → ISR +~800 cycle → 总负载过高
  → FreeRTOS 发送任务得不到调度（uart_task_loops=0）
  → READY 缓冲无人取 → acquire_fail 暴涨 → VOFA 停

关掉 nor → isr_delta ~2700 → 任务/DMA 正常
```

**不是** RTOS 栈太重，而是 **20kHz ISR 占满 CPU 时间片**；提优先级救不了 nor 开时的饿死。

## 三、当前架构（工作配置）

```
TIM1 20kHz ISR
  ├─ AS5047 SPI1 读角度（~1500 cycle）
  ├─ setPhaseVoltage()  ← 必须轻量（nor 关时 ~1000 cycle 级）
  ├─ telem_bringup_tick() 写双缓冲（~60 cycle 均摊）
  └─ DWT → g_telem_dbg.isr_delta

FreeRTOS: UART_DMA_DEBUG 任务
  └─ telem_bringup_try_send() → HAL_UART_Transmit_DMA @ 6Mbps

TxCplt → 缓冲 SENDING → UNLOCKED
```

**VOFA+**：6000000，JustFloat，4 通道。  
**ch1/ch2** 为 uint32 小端，VOFA 当 float 显示 ~0 → 看 Watch `isr_delta` / `ch2_wire`。

## 八、明天建议第一步

在 `bringup/trans.c` 做 **bringup 版轻量 `setPhaseVoltage`**：

```c
// 用 angle_el 算扇区，勿 atan2/fmod
sector = (int)(angle_el / _PI_3) % 6 + 1;
// Uref 常数或 Uq/母线，勿 sqrt
Uref = fabsf(Uq) / voltage_power_supply;
```

目标：**`isr_delta` < 3000**，Watch 里 `uart_task_loops` 持续增长，VOFA 与电机同时跑。
