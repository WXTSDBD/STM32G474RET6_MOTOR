# 代码注释规范

**日期**：2026-10-06  
**修订**：2026-10-06，同一约束只写一处；注释不得触发 `-Wcomment`；纯注释提交不改逻辑。同日再改：宏样例只用仍被读到的宏；预处理验收用 `-E -dM`，不用 `-E -dD`。  
**对象**：本仓库自研 C 代码（新文件，以及给旧文件补注释）  
**不替代**：架构文档、施工方案、GATE / 联调报告。那些仍放在 `docs/`，见本文 §2。

后来者打开 Keil、手头没有聊天记录时，应能知道：这个文件管什么、这个量是干什么的、调错会怎样。调用节拍和中断限制写在对应 `.h` 的文件头里，IDE 点到声明时先看见的是那里。

---

## 1. 适用范围

要写注释的目录：

- `motor/`、`config/`、`board/`、`platform/`、`bringup/`、`Drivers/` 里自研部分

不写、也不要为了补注释去改：

- CubeMX 生成的 `Core/Src/*.c`、`Core/Inc/*.h`（Generate 会覆盖；业务放在自研目录）
- 第三方 Middleware、CMSIS、HAL 库本体
- `tools/*.py`、纯数据表（烤好的 LUT 大数组）。数组若有单位或生成方式，在声明上方写一行即可

`.h` 与 `.c` 都要有文件头。函数的块注释只写在 `.c`（或写在 `.h` 里的 `static inline` 函数体上）。`.h` 里的函数声明上面不写注释。

## 2. 注释和文档怎么配合

两边都要有，写的不是同一件事。

| | 代码注释 | `docs/` |
|---|---|---|
| 跟着什么走 | 跟着这几行代码，改代码必须改注释 | 跟着一次设计或一次台架 |
| 读者要能独立看懂的 | 职责、单位、调用节拍、状态怎么进出、改错的直接后果 | 整条路径、为什么当年否掉某个参数、某次录波 |
| 可以落后吗 | 不可以。注释和代码不一致就删掉或改掉 | 可以。报告是历史 |

注释必须自洽，并且同一条约束只写一处。调用方能不能在任务里调、必须从哪个中断进，只看该 `.h` 的文件头。角度单位、这一段内部顺序，看声明旁边的类型说明或 `.c` 里的函数注释。想查「哪次录波把这个门限打回来的」，再去 `docs/`。

注释里可以 `@see` 一份**仍然有效**的文档，并写到章节，例如架构总册或当前冻结说明。不要写「详见 docs」。实验编号（`GATE52`、`S3c0b`、`C4n`）、VOFA 时间戳、试过哪些档，只留在报告里。代码里只留现在仍然成立的物理结论。

## 3. 两种注释，各用在哪

| 写法 | 用在 |
|---|---|
| `/** ... */` | 文件头、类型、枚举、文件级变量、结构体成员、宏的总说明、`.c` 里的函数 |
| `/* ... */` | 函数体内少数行；某一条宏的行尾单位说明 |

正文用中文。保留英文的只有标签和符号名：`@file`、`@date`、`@brief`、`@param`、`@return`、`@note`、`@see`，以及 `θ̂`、`Id`、`JEOC` 这种代码里就这么叫的名字。`θ̂` 和中文可以留。不要混进损坏的 GBK 或替换字符。

块注释正文里不得再出现连续的斜杠和星号（`/*` 这两个字符挨在一起）。armclang 默认 `-Wcomment`，会报 `warning: '/*' within block comment`。链接仍是 0 Error，但 Warning 计数加 1，本仓库的 0 Warning 验收失败。电压和指针形参写成「ud、uq」或「ud/uq」，不要写成「*ud」。星号贴在标识符前面，前一个词若以斜杠结尾，就会拼出这个字符序列。

不新写 `//` 注释。旧的行首 `//` 数量很少，碰到那一行、或趁补注释时一并改成上面两种，不必单独开一轮。

标签含义：

| 标签 | 写什么 |
|---|---|
| `@file` | 文件名，含扩展名 |
| `@date` | 本文件头第一次写入的日期，`YYYY-MM-DD`。写入后不改。后补的旧文件，这个日期是补头那天，不是臆造的诞生日期 |
| `@brief` | 一句话：这个文件或函数做什么 |
| `@param` | 参数含义、单位、谁可以传 `NULL` |
| `@return` | 返回值含义。无返回值不写 |
| `@note` | 只写这个函数内部的约束：语句顺序、和 profile 的关系、不暴露给调用方的状态。不复述节拍和中断号 |
| `@see` | 仍有效的文档路径加章节，可选 |

## 4. 文件头（`.h` 和 `.c` 都要）

放在文件最上面，在 `#ifndef` 保护宏或 `#include` 之前。两份都写 `@date` 和职责。`.h` 写给调用方，`.c` 写给改实现的人。同一句话不要贴两遍。

`.h` 至少包含：这个头对外提供什么。对外函数若调错会打电机（节拍、哪一个中断、禁止在任务里重入），约束写在这个文件头里，不要写在某条声明上面，也不要只写在 `.c` 的 `@note` 里。  
`.c` 至少包含：本文件负责什么、不负责什么。实现上的顺序和 profile 关系写在对应函数的 `@note`。节拍和中断号若已写在 `.h` 文件头，`.c` 不再复述。

有硬件绑定时，把映射表写在负责填写的那个文件头里（现成例子是 `config/bridge_cubemx.c`）。改绑定要同时改这张表。

```c
/**
 * @file motor_current.h
 * @date 2026-10-06
 * @brief M1 电流环对外入口：初始化、20 kHz 节拍、模式与电流指令。
 *
 * 调用方只通过本头改模式和指令。Park 角从哪来、PI 怎么算，不在本头展开。
 * motor_current_tick() 只允许从 ADC 注入转换完成中断调用。
 */
```

```c
/**
 * @file motor_current.c
 * @date 2026-10-06
 * @brief M1 电流环节拍编排：采样、选 Park 角、电流 PI、SVPWM。
 *
 * 本文件负责把一步串起来，并在编码器 / I-f / 观测器之间选角度。
 * 本文件不填 HAL 句柄，不含 HFI 解调。观测器算法在 motor/observer/。
 * 节拍和中断限制见 motor_current.h 文件头，这里不重复。
 *
 * @note 本头为后补。源文件更早，诞生日期以 git 为准。
 * @see docs/电机驱动软件框架——完整架构设计文档_v3.0.md 热路径一节
 */
```

后补旧文件时保留最后那句 `@note`，避免 `@date` 被当成文件诞生日期。新文件不要写这句。

## 5. 函数

### 5.1 写在哪

- 定义在 `.c` 里的函数（含 `static`）：块注释写在 `.c` 的定义上方。
- `.h` 里只留声明，声明上方不写 `/** */`，也不写行尾注释。
- 函数体直接写在 `.h` 里的 `static inline`：块注释写在 `.h` 该函数上方，因为没有别的地方可写。

新文件，以及本轮正在改的函数：每个函数（含 `static`）都要有 `@brief`，一行说清做什么。旧文件不要一次铺满，顺序见 §12。一次给上百个 `static` 补 `@brief`，diff 会把真正的行为改动淹没。纯注释的验收只看 Size 和 `-E -dM` 宏表（§15），铺满不增加可信度。

### 5.2 什么时候加 `@param` / `@return` / `@note`

- 参数带单位、指针可否为空、取值范围会影响电机：写 `@param`。
- 返回值不是一目了然的成功/失败：写 `@return`。
- 函数内部的语句顺序、和 profile 绑在一起、调用方从声明上看不见的状态约束：写 `@note`。
- 节拍、中断号、禁止在任务里调用：不写在这里。写在该 `.h` 的文件头，且只写那一处。

名字已经说明全部含义、且没有单位和内部顺序问题的函数，只留 `@brief`。

```c
/**
 * @brief 电流环一步：采样，选 Park 角，电流 PI，SVPWM。
 * @param axis 轴实例。M1 以外当前直接返回。不可为 NULL。
 * @note 编码器可选打开且没有编码器时，沿用上一拍 Park 角，禁止改回读取 θ_enc。
 */
void motor_current_tick(bsp_axis_t *axis)
```

对应的 `.h` 里是裸声明：

```c
void motor_current_tick(bsp_axis_t *axis);
```

## 6. 变量

要让人看出这个量是干什么的、单位是什么、1 和 0 各表示什么。注释写在声明上方，用 `/** */`。一行能说清就一行。

必须写：

- 文件级变量、`static` 状态（会活过一次函数调用的）
- 结构体、联合体的每个成员
- 全局
- 局部变量里名字看不出用途或单位的（锁存的指令、冻结的电流、上一拍角度）

可以不写：

- 循环下标 `i`、`n`
- 函数开头拿来接返回值、立刻用掉的临时量，且名字已经是 `id_a`、`dt_s` 这种带单位的

同一块状态可以上面先用一段话说整组是干什么的，再给每个变量一行。不要只写组说明、下面五个变量没有一个字。

```c
/** 观测器速度 PLL。输入是电角，输出经换算得到机械转速。只在观测器速度反馈路径使用。 */
static motor_pll_t s_obs_spd_pll;
/** 1=已经用第一帧电角对齐过；0=下一帧要先对齐，不能当转速用。 */
static uint8_t s_obs_spd_pll_primed;
/** PLL 换算后的机械转速，单位 rpm。在 20 kHz 节拍里按速度环分频更新。 */
static float s_obs_spd_pll_rpm;

/** 1=已经从 I-f 进入观测器，I-f 不再接管。 */
static uint8_t s_if_to_obs_handed;
/** 释放前最后一拍 I-f 速度指令，单位 rpm。 */
static float s_if_omega_cmd_latched;
```

结构体成员同样写在成员上方。调用方要靠 `.h` 读懂的字段，注释写在 `.h` 的类型定义里，`.c` 不要再抄一遍。

```c
/* 节选。成员名与 config/bsp_axes.h 一致，不是完整定义。 */
typedef struct {
    /** 1=本轴参与初始化；0=只占位，不调用 adc_sample_init。 */
    bool enabled;
    /** 本轴编码器实例。 */
    encoder_t *enc;
} bsp_axis_t;
```

## 7. 宏

仍被读到的每条 `#define` 都要能看出：干什么、单位、改了会怎样。例外：头文件保护宏（`#ifndef MOTOR_CURRENT_H` 那种）、纯别名且名字已经等于含义的宏、以及下文说的没有引用点的宏。

同一机制的好几条宏：在第一行上面用一块 `/** */` 写共同规则，每条再写本条的含义。本条说明若只有单位或换算，用行尾 `/* */`。

可被 `config/profiles/` 覆盖的默认值，在 `#ifndef` 上方写明「默认；profile 可覆盖」。

```c
/**
 * 踢段结束后的位移门槛，单位电角 rad。默认 0.03，约 1.7°。
 * |Δθ_enc| 低于此值视为没有转起来。
 * 编码器可选编译打开时不拒判，按北锁；否则拒判并进入故障锁。
 * 这是故障门。补注释不改这个数。
 */
#ifndef M1_HFI_QKICK_DTH_MIN_RAD
#define M1_HFI_QKICK_DTH_MIN_RAD        0.03f
#endif

/** 高频注入电压幅值，单位 V。复位时写入注入幅值。默认 2.0；profile 可覆盖。 */
#ifndef M1_HFI_VH_V
#define M1_HFI_VH_V                     2.0f
#endif

/** PLL 角误差死区，单位 rad。复位时写入。0 表示关闭。默认 0；profile 可覆盖。 */
#ifndef M1_HFI_PLL_EPS_DEAD
#define M1_HFI_PLL_EPS_DEAD             0.0f
#endif
```

只有定义、没有引用点的宏，改了不会怎样，不写「改了会怎样」。这种宏标「当前未用」，或者留着不写，不进第一刀。`M1_HFI_POLARITY_ERR_RAD`、`M1_HFI_POLARITY_PI_RAD`、`M1_HFI_UNLOCK_HOLD_N` 现在就是这样。

上面三条样例都在 `motor/observer/hfi_sqwave.c`，不在 `motor_params_m1.h`。`hfi_sqwave.c` 的第一刀写这几条仍被读到的：故障门、注入幅值、PLL 死区。故障门只加注释，不改数值。

`motor_params_m1.h` 有上千条宏，不要按「每条都写」做第一刀，也不要到那个文件里找上面三条。那里只写仍被读到的，例如发布门槛和速度反馈里还有引用点的，格式与上面相同。头文件保护宏和纯别名不写。其余宏以后改到哪条再补哪条。

时间宏写清拍和秒的换算。角度宏写清电角还是机械角。电流宏写 A，电压宏写 V，转速宏写 rpm 还是 rad/s。

不要在宏注释里写实验编号。门限若来自台架，注释写电机侧现象（例如「一拍把 Id 拉满会打到滑模观测器」），编号留在 `docs/` 的报告里。

## 8. 类型和枚举

写在 `.h` 的类型上方。每个枚举值一行，说明这一态代表什么、和前后态的关系。状态机的整条路径写在枚举类型的块注释里，不要散落在各个宏上面。

```c
/**
 * 无感起动阶段。
 * HOLD：锁在 2θ，注入电压开着，Iq=0。
 * CAPTURE：固定 Iq，叠电子阻尼，Park 仍用估计角。
 * HANDOVER：力矩角从踢距转到运行角。这一段解调不能再把 Park 角当成估计角。
 * RUN：交给速度环。Id 缓慢放开，禁止一拍拉满。
 * CAPTURE 结束后若不再开无感速度环，停在 DONE。
 */
typedef enum {
    /** 未开始。 */
    HFI_STAGE_IDLE = 0,
    /** 锁 2θ，等待极性确认。 */
    HFI_STAGE_HOLD = 1,
    /** 固定 Iq 把转子从静止带离。 */
    HFI_STAGE_CAPTURE = 2,
    /** 把角度从起动角交到运行角。 */
    HFI_STAGE_HANDOVER = 3,
    /** 速度环运行。 */
    HFI_STAGE_RUN = 4,
    /** 捕获结束且不再交接。 */
    HFI_STAGE_DONE = 5
} hfi_stage_t;
```

上面的 `HOLD` / `CAPTURE` 只示范版式，不是 `hfi_sqwave` 里的阶段名。补 `hfi_sqwave.h` 时对着源码里的真实枚举写：`IDLE`、`MOVE`、`SETTLE`、`MEAS`、`LOG`、`DONE`、`CRAWL`、`RUN`。不要改枚举值，也不要把样例里的名字写进那个文件。

## 9. 函数体内的行注释

用 `/* */`，只写代码看不出来的事：为什么这样分支、这个顺序不能换、这一拍故意不更新。

```c
/* 只切角度：交到观测器之后 Iq 钉在切换前的值，避免交角瞬间力矩阶跃 */
s_if_obs_iq_freeze = iq_cmd;
```

不写「把 iq_cmd 赋给 s_if_obs_iq_freeze」这种复述。循环、显而易见的返回、纯算术，不加注释。

---

## 10. 不要写的

- 实验过程：`GATE52`、`S3c0b`、`C4n`、某次 CSV 文件名、试过 300 可以 400 不行。
- 复述下一行代码已经写出的动作。
- 会过期的计划：「下一步改成 Composite」「本轮先不动」。
- 半句、乱码、中英各半截。这种注释补的时候改成完整句或删掉。
- `.h` 函数声明上的块注释（`static inline` 除外）。
- 把 `docs/` 里的方案全文贴进文件头。文件头三到十行够用。

## 11. 成套样例

下面是一份虚构的小模块，用来对照版式。不要把这段抄进工程。

`angle_hold.h`：

```c
/**
 * @file angle_hold.h
 * @date 2026-10-06
 * @brief 有感位置保持的对外入口：锁存当前位置，并给出 Iq 指令。
 *
 * 只在速度环已经闭合、转子已停时调用 angle_hold_arm。转动中调用会把当前角当成目标，造成制动冲击。
 * 本头不提供观测器角度。angle_hold_iq_ref 由 2 kHz 外环读取。
 */
#ifndef ANGLE_HOLD_H
#define ANGLE_HOLD_H

#include <stdint.h>

#ifdef __cplusplus
extern "C" {
#endif

typedef struct {
    /** 锁存的机械角指令，单位 rad。arm 时写入，之后只被本模块改。 */
    float theta_ref_rad;
    /** 1=已经锁存，Iq 由角度误差产生；0=直通外部 Iq。 */
    uint8_t armed;
} angle_hold_t;

void angle_hold_init(angle_hold_t *hold);
void angle_hold_arm(angle_hold_t *hold, float theta_now_rad);
float angle_hold_iq_ref(const angle_hold_t *hold, float theta_now_rad);

#ifdef __cplusplus
}
#endif

#endif /* ANGLE_HOLD_H */
```

`angle_hold.c`：

```c
/**
 * @file angle_hold.c
 * @date 2026-10-06
 * @brief 有感位置保持：把角度误差变成 Iq 指令。
 *
 * 本文件只做保持，不切换 Park 角，不碰 PWM。
 * 谁在什么节拍调用见 angle_hold.h 文件头，这里不重复。
 */

#include "angle_hold.h"

/**
 * 角度误差到 Iq 的比例，单位 A/rad。
 * 默认偏软，避免 arm 时机械角噪声打出电流尖峰；profile 可覆盖。
 */
#ifndef ANGLE_HOLD_KP_A_PER_RAD
#define ANGLE_HOLD_KP_A_PER_RAD         0.4f
#endif

/** Iq 绝对值上限，单位 A。超过则截断，避免保持环在顶死电流下积分。 */
#ifndef ANGLE_HOLD_IQ_ABS_MAX_A
#define ANGLE_HOLD_IQ_ABS_MAX_A         1.5f
#endif

/**
 * @brief 清掉锁存，回到直通外部 Iq。
 * @param hold 保持状态。不可为 NULL。
 */
void angle_hold_init(angle_hold_t *hold)
{
    hold->theta_ref_rad = 0.0f;
    hold->armed = 0u;
}

/**
 * @brief 把当前机械角锁成指令，并开始输出保持 Iq。
 * @param hold 保持状态。不可为 NULL。
 * @param theta_now_rad 当前机械角，单位 rad。
 */
void angle_hold_arm(angle_hold_t *hold, float theta_now_rad)
{
    hold->theta_ref_rad = theta_now_rad;
    hold->armed = 1u;
}

/**
 * @brief 由角度误差计算 Iq 指令。
 * @param hold 保持状态。不可为 NULL。
 * @param theta_now_rad 当前机械角，单位 rad。
 * @return Iq 指令，单位 A，已按绝对值上限截断。未 arm 时返回 0。
 */
float angle_hold_iq_ref(const angle_hold_t *hold, float theta_now_rad)
{
    float iq_a;

    if (hold->armed == 0u) {
        return 0.0f;
    }

    iq_a = ANGLE_HOLD_KP_A_PER_RAD * (hold->theta_ref_rad - theta_now_rad);
    if (iq_a > ANGLE_HOLD_IQ_ABS_MAX_A) {
        iq_a = ANGLE_HOLD_IQ_ABS_MAX_A;
    } else if (iq_a < -ANGLE_HOLD_IQ_ABS_MAX_A) {
        iq_a = -ANGLE_HOLD_IQ_ABS_MAX_A;
    }

}
```

## 12. 给旧文件补注释的顺序

不要把整棵 `motor/` 做成注释专项，也不要按目录一次铺满。新文件和本轮正在改的函数按 §5 写满。旧文件按下面的顺序，先写后来者打开就会改错的地方：

1. `motor/motor_current.h` 的文件头：20 kHz、只许 ADC 注入转换完成中断调用。`motor/motor_current.c` 的文件头写编排职责和角度从哪来，不把中断限制再写一遍。
2. `motor/observer/` 里正在用的状态机：文件头、真实枚举（见 §8）、电流软放开。宏只补这一路径仍被读到的那几条（见 §7）。没有引用点的极性宏不要补。
3. 对外 `.h` 的类型、枚举、结构体成员。函数声明保持裸声明。
4. 改到哪个 `static`，再给那个函数补 `@brief`。不要为了整齐，把文件里每个 `static` 一次补完。

`motor_params_m1.h` 的第一刀范围见 §7，不要铺完整文件。

补的时候删掉半句和实验编号，改成本文的完整句。不为注释去改逻辑、改枚举值、改宏数值，也不为注释去动故障门、`INIT_FROM_ENC`，或去还要重录金样才许动的结构债。

## 13. 以后改代码时

- 改了节拍或中断限制：只改该 `.h` 的文件头。`.c` 的 `@note` 不要跟着复述。`.h` 的声明仍然不写注释。
- 改了函数内部顺序、单位、参数含义：改 `.c` 里该函数的块注释。
- 改了文件职责：改该文件头的 `@brief` 和正文。`@date` 不动。
- 改了宏的含义或单位：改宏注释。只改数值、含义不变：注释不用重写，除非换算关系变了（例如拍数还写着 10 ms，实际已经不是）。
- 删掉一段代码：把它专属的注释一起删掉。
- 改了 `bridge` 一类的硬件映射：文件头里的映射表一起改。

## 14. 编码

源文件使用 UTF-8，无 BOM。

不要用 PowerShell 的 `Get-Content` / `Set-Content` 整文件改写。中文 Windows 上这一对默认按系统代码页往返，UTF-8 会先被读成 GBK，再存一次中文就坏。补注释用编辑器或明确指定 UTF-8 无 BOM 的写入。

不要引入字节 `0x85`。它不是 UTF-8 里的中文，混进去之后中文注释会再次损坏。

## 15. 纯注释提交

注释单独提交，不夹带改逻辑、改宏数值、改枚举。这种提交不算解冻。

验收相对动手前那一次 Rebuild，不是一组写死在本文里的永久 Size。动手前从 `MDK-ARM/rebuild_log.txt` 抄下 `Program Size` 那一行。2026-10-06 当前树是 `Code=68628 RO-data=1972 RW-data=76 ZI-data=21876`，0 Error，0 Warning。树若已经因别的提交变过，以抄下来的那一行为准，不要回头套这组数字。补完必须满足：

- Rebuild 的 `Program Size` 与抄下的那一行逐字相同，且仍是 0 Error、0 Warning。
- 改过的翻译单元，用 armclang `-E -dM` 做前后对比，宏表 diff 为 0。`-dM` 只倒宏，不加行号，不受注释行数和空行影响。

不要用 `-E -dD` 当通过条件。它会留下 `# 行号 "文件"` 标记，加一行注释，后面的行号就漂，diff 不为 0。这不表示宏或逻辑变了。为了让它归零去删注释，验收就反了。HAL 的 `assert_param` 使用 `__LINE__`，带行号的展开本来也会随注释行数变；自研目录里没有 `__LINE__`。若要看正文展开，用 `-E -dD -P`，并忽略空行差异。`-P` 去掉行号标记，空行仍可能差一行。

只有改到 `s_eps`、AUTH、ATAN2 或 12 通道映射，才需要重录金样。纯注释不动这些，不重录。
