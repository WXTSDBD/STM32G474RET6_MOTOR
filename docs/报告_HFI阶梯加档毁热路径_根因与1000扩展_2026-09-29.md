# 报告：HFI 速度阶梯「加 400 毁 100 rpm」根因与签收（2026-09-29）

**对象**：`M1_HFI_GATE=51`（S2i）· Park=θ̂ · 速度环吃编码器 · ch8=PLL 积分  
**约束**：编码器只作尺子；无 I/F / enc ω_ff 拐杖。

---

## 0. 一句话

> **问题不是「400 rpm 转不动」，也不是 Flash 装不下。**  
> 旧写法把多档转速写进 **FOC 每拍都调用的取速函数**（浮点 if / 查表），加第四档会 **重写热路径机器码**，表现为一进 RUN 就在 **100 rpm** 失锁（θ̂≈−90°、Iq 钉满）。  
> **改法**：热路径只读变量 `s_run_rpm_cmd`；每 7 s 在 `on_angle` 里 `+=100`。加档只改 `MAX` 与总时长常量。  
> **台架**：变量阶梯到 300（2007）、到 400（用户确认）均 PASS → 根因成立。现行扩展到 **1000 rpm**。

---

## 1. 现象回顾

| 包 | 写法 | 上限 | 100 rpm 结果 |
|----|------|------|----------------|
| 1948 | s2d + ext（if） | 300 | PASS（err≈−5°，Iq≈0.26） |
| 1942 | if 链含 400 | 400 | FAIL（指令仍 100；θ̂≈−95°；Iq 顶满） |
| 1959 | 查表 + `optnone` 含 400 | 400 | FAIL（更重：每拍 VDIV） |
| 2007 | `s_run_rpm_cmd` | 300 | PASS，100/200/300 丝滑 |
| （用户） | 同左 | 400 | **PASS**（确认可到 400） |

「卡死」= 失锁振荡，不是 HardFault。

---

## 2. 根因（已钉死）

### 2.1 直接原因

在 **热路径**（`hfi_sqwave_get_speed_ref_rpm` ← 电流环每拍）里用多路浮点分档：

- 编译器内联 / 重排 → 加一档就改写前两档的机器码形态；或  
- `optnone` 查表 → 每拍 VDIV + 栈，拖垮时序。

相关的是 **「加档是否改变热路径代码」**，不是常量「400」或 400 rpm 工况（挂时从未跑到 400）。

### 2.2 排除项

| 猜测 | 结论 |
|------|------|
| 代码太大 | 否。旧版 +24 B；变量阶梯下 MAX 300↔400 **Code 同为 56284** |
| RUN 总时长太长 | 否。100 rpm 在 t≈0 |
| 400 rpm 物理/摩擦 | 否。挂在第一档 |
| 数字 400 与其它宏撞车 | 否。图中本就有其它 400 常量；300 PASS 可证 |

### 2.3 A/B（变量阶梯，只改 MAX）

`hfi_sqwave.o` 仅差 3 字节：`run_total` 21→28、封顶比较 300.5→400.5。  
`get_speed_ref` / `on_current` **指令级相同**。快照见 `MDK-ARM/_abin_cmp/C_max300.*`、`C_max400.*`。

---

## 3. 正确结构（现行）

```text
FOC 每拍:  speed_ref = s_run_rpm_cmd          // 一条读
on_angle:  每满 STEP_S 秒: cmd += STEP（≤ MAX）
```

| 宏 | 现行 |
|----|------|
| `M1_HFI_RUN_RPM_START` | 100 |
| `M1_HFI_RUN_RPM_STEP` | 100 |
| `M1_HFI_RUN_RPM_MAX` | **1000** |
| `M1_HFI_RUN_STEP_S` | 7 |
| RUN 总长 | 10 档 × 7 s ≈ **70 s**（另 + IDLE 5 s） |

加更高转速：只改 `MAX`，不要把档位 if/表塞回 `get_speed_ref`。

验收建议：先录再复位；录满至 DONE；看各档 `w_ref` / `w_enc` / 积分转速 / `θ_err` / Iq。若某档掉锁，记转速点（那是控制/观测边界，不是「加档毁编译」）。

---

## 5. 教训

1. **联调阶梯：热路径保持「读一个量」**；分档状态机放慢路径。  
2. 「改宏就炸低速」优先怀疑 **代码生成/热路径形态**，不要先怪工况。  
3. A/B 用 `fromelf` 比 `.o`：若取速/PLL 不变，就不是编译器幽灵。
