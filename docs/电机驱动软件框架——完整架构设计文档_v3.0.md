## 一、领域划分

整个固件分为两个互不调用的域，只通过共享数据区交换信息。

```Plaintext
┌──────────────────────────────────────────────────────────────────┐
│                         Application 层                            │
│                 系统初始化编排、生命周期管理、模式调度               │
├────────────────────────────┬─────────────────────────────────────┤
│    通信域 (Comms Domain)    │       控制域 (Motor Domain)          │
│                            │                                      │
│  FDCAN / CANopen           │  20kHz FOC 热路径                    │
│    ├─ SDO (参数读写)        │    电流采样 → Clarke/Park            │
│    ├─ PDO (控制指令/反馈)   │    → 电流环PI → 死区补偿             │
│    ├─ NMT/Heartbeat/EMCY   │    → 前馈 → Park逆 → SVPWM           │
│    └─ OTA (固件升级)        │                                      │
│  LPUART (调试遥测 5Mbps)   │  2kHz 速度环 / 位置环                 │
│  UART1 (OTA 备用)          │  观测器 (有感 / SMO / HFI；ESO 未做)  │
│  串口命令行 (CLI)           │  参数辨识 / 标定 / 自整定（目标）      │
│  OLED / LED 灯语           │                                      │
│                            │  三角函数 (硬件CORDIC / 查表+插值)     │
│  运行方式: RTOS 线程        │  运行方式: 裸机中断驱动                │
├────────────────────────────┴─────────────────────────────────────┤
│                        共享数据区                                  │
│  ControlCommand (通信域→控制域) / MotorTelemetry (控制域→通信域)    │
└──────────────────────────────────────────────────────────────────┘
```

**关键约束**：

- 控制域绝不调用通信域的任何函数  
- 通信域绝不调用控制域的任何函数  
- 域间只通过共享数据结构交换信息

## 二、五层架构

```Plaintext
┌──────────────────────────────────────────────┐
│  App 层                                      │
│  系统初始化编排、生命周期管理、模式切换调度     │
│  唯一知道所有具体类型的地方                    │
├──────────────────────────────────────────────┤
│  Service 层                                   │
│  纯逻辑层，不碰任何寄存器                      │
│  motor/ | comms/ | ota/ | calibration/       │
│  fault/ | test/  | debug/                    │
├──────────────────────────────────────────────┤
│  Platform 层                                  │
│  板级定义、引脚映射、资源分配、产品配置         │
├──────────────────────────────────────────────┤
│  Driver 层                                    │
│  按功能域分组，封装 HAL，提供 C ops 接口       │
│  encoder/ | current_sense/ | gate_driver/    │
│  power_stage/ | storage/ | display/ | comm/  │
│  adc/     | math/ (三角函数)                  │
├──────────────────────────────────────────────┤
│  HAL 层 (ST 提供，手动不改)                    │
└──────────────────────────────────────────────┘
```

**依赖规则**：单向依赖，上层只依赖下层接口。下层完全不感知上层。跨层访问绝不允许。

### 关节电机 / 异板可迁移硬约束

- **控制域算法与板级解耦**：`motor/`（FOC、观测、外环、辨识）不绑死本板引脚或 CubeMX 句柄名；板差进 Platform / `config` / profile  
- **产品与电机差异用 profile**：如 `config/profiles/*.profile.h`、电机参数头；禁止为换电机复制整棵控制树  
- **迁移目标**：同一套 FOC / 观测 / 外环可搬到**关节电机驱动**——换电机参数、采样与功率级驱动适配、有感或无感策略选择；通信域（CANopen/OTA/OLED）可裁剪  
- App 层是唯一组装点：选定 profile、绑定 Driver ops、启动中断

## 三、对象模型

每个对象 = cfg + ctx + data + ops：

```Plaintext
┌────────────┬─────────────────────────────────┐
│ cfg        │ 静态配置                          │
│            │ 引脚号、波特率、PI参数默认值        │
│            │ 编译期确定或初始化时填入，运行期只读  │
├────────────┼─────────────────────────────────┤
│ ctx        │ 运行时上下文                       │
│            │ 状态机状态、计数器、时间戳、busy标志  │
│            │ 只有对象自己能修改                  │
├────────────┼─────────────────────────────────┤
│ data       │ 当前处理的数据                     │
│            │ 电流值、角度、速度、指令值           │
│            │ 对外只读或通过原子操作访问           │
├────────────┼─────────────────────────────────┤
│ ops        │ 行为接口（C 函数指针表）             │
│            │ init/start/process/stop           │
│            │ 编译期宏选具体实现，或 init 时填表   │
└────────────┴─────────────────────────────────┘
```

策略切换优先用 **编译期宏 / profile**（零虚表开销）；需要运行期可替换时用 **ops 函数指针表**，init 后指针冻结。

### 4.2 核心接口定义（C ops 示意）

```C
/* 观测器 */
typedef struct {
    bool  (*init)(void *self);
    void  (*update)(void *self, float ia, float ib, float ua, float ub);
    float (*get_theta)(const void *self);
    float (*get_omega)(const void *self);
    bool  (*is_converged)(const void *self);
    void  (*reset)(void *self);   /* 可为 NULL */
} observer_ops_t;

/* 前馈 */
typedef struct {
    float (*compute_ud)(void *self, float id_ref, float iq_ref, float omega);
    float (*compute_uq)(void *self, float id_ref, float iq_ref, float omega);
} feedforward_ops_t;

/* 死区补偿 */
typedef struct {
    bool (*learn)(void *self);
    void (*compensate)(void *self, float ia, float ib, float *ua, float *ub);
} deadband_ops_t;

/* 指令处理（ESO / MTPA / MIT 挂这里） */
typedef struct {
    void (*process)(void *self, float *id_ref, float *iq_ref,
                    float omega, float load_est);
} cmd_proc_ops_t;

/* 电流采样 */
typedef struct {
    bool  (*init)(void *self);
    void  (*sample)(void *self, float *ia, float *ib);
    float (*get_vbus)(const void *self);
    float (*get_temp)(const void *self);      /* 可为 NULL */
    void  (*calibrate_offset)(void *self);    /* 可为 NULL */
} current_sensor_ops_t;

/* PWM */
typedef struct {
    bool    (*init)(void *self, const pwm_config_t *cfg);
    void    (*set_duty)(void *self, uint8_t motor_index, const pwm_output_t *duty);
    void    (*enable)(void *self, uint8_t motor_index);
    void    (*disable)(void *self, uint8_t motor_index);
    void    (*emergency_off)(void *self, uint8_t motor_index);
    uint8_t (*motor_count)(const void *self);
} pwm_timer_ops_t;

/* 三角函数 (Driver/math) */
typedef struct {
    void  (*sincos)(void *self, float theta, float *s, float *c);
    float (*atan2)(void *self, float y, float x);
    float (*sin)(void *self, float theta);
} trig_ops_t;
```

具体观测器实现（编码器 PLL / SMO / HFI）各自提供 `xxx_ops` 常量与 `self` 上下文；App/profile 在启动时选定一版。**ESO 尚未实现**，预留挂在 `cmd_proc_ops`。

### 4.3 三角函数实现选择

| 实现 | Park | PLL atan2 | 扫频 sin | 移植性 |
|------|------|-----------|----------|--------|
| 硬件 CORDIC (G474) | 12 cycle | 12 cycle | 12 cycle | 仅 G4 |
| 查表 256+插值 | 20 cycle | arm_atan2 ≈200 | 20 cycle | 全平台 |
| CMSIS-DSP | ≈200 | arm_atan2 | arm_sin | 全平台 |

**策略**：FOC ISR 用硬件 CORDIC（独占，prio 0）；扫频用查表+插值。通过 `trig_ops_t` 各自持有独立实例。

### 4.4 MotorCore 热路径（C 示意）

```C
typedef struct {
    const current_sensor_ops_t *current;
    void                       *current_self;
    const pwm_timer_ops_t      *pwm;
    void                       *pwm_self;
    const trig_ops_t           *trig;
    void                       *trig_self;
    uint8_t                     motor_index;

    const observer_ops_t       *observer;
    void                       *observer_self;
    const deadband_ops_t       *deadband;     /* 可为 NULL */
    void                       *deadband_self;
    const feedforward_ops_t    *ff;           /* 可为 NULL */
    void                       *ff_self;
    const cmd_proc_ops_t       *cmd_proc;     /* 可为 NULL；ESO 挂此 */
    void                       *cmd_proc_self;
    /* ... PI、遥测缓冲等 ctx/data ... */
} motor_core_t;

/* 20kHz TIM 中断直接调用 */
void motor_core_tick(motor_core_t *m)
{
    float ia, ib;
    m->current->sample(m->current_self, &ia, &ib);
    m->observer->update(m->observer_self, ia, ib, m->ud_ref, m->uq_ref);
    m->theta = m->observer->get_theta(m->observer_self);
    m->omega = m->observer->get_omega(m->observer_self);

    clarke_park(ia, ib, m->theta, &m->id, &m->iq);

    m->ud_ref = foc_pi_tick(&m->id_pi, m->id_ref, m->id);
    m->uq_ref = foc_pi_tick(&m->iq_pi, m->iq_ref, m->iq);

    if (m->deadband) {
        m->deadband->compensate(m->deadband_self, ia, ib, &m->ud_ref, &m->uq_ref);
    }
    if (m->ff) {
        m->ud_ref += m->ff->compute_ud(m->ff_self, m->id_ref, m->iq_ref, m->omega);
        m->uq_ref += m->ff->compute_uq(m->ff_self, m->id_ref, m->iq_ref, m->omega);
    }

    float ta, tb, tc;
    inv_park_svpwm(m->ud_ref, m->uq_ref, m->theta, m->v_bus, &ta, &tb, &tc);
    pwm_output_t duty = { ta, tb, tc };
    m->pwm->set_duty(m->pwm_self, m->motor_index, &duty);
}

void motor_core_speed_tick(motor_core_t *m)
{
    if (!m->enabled) return;
    float omega_err = m->omega_ref - m->omega;
    m->iq_ref = foc_pi_tick(&m->speed_pi, omega_err, 0.0f); /* 示意 */
    if (m->cmd_proc) {
        m->cmd_proc->process(m->cmd_proc_self,
                             &m->id_ref, &m->iq_ref, m->omega, m->load_est);
    }
}
```

**tick() 开销分析 @ 160MHz**：有感路径合计约 ~680 cycle / 8000（20 kHz），占比约 8.5%。

## 五、通信域完整设计

### 5.1 CANopen 精简策略

**保留（CiA 301 兼容骨架）**：

- SDO server（OD 读写）— 参数配置、OTA 触发、诊断  
- NMT slave — 节点状态管理  
- Heartbeat — 连接监控  
- EMCY — 紧急故障报文  
- SDO segmented transfer — OTA 固件传输  

**裁减（不声称完整 CiA 402）**：

- CiA 402 状态机 → 精简为三态：IDLE → ENABLED → FAULT  
- PDO 映射 → 自定义，只保留实际需要的对象  
- 大量 Optional 对象 → 不实现，SDO 读返回 Abort `0x06020000`  

### 5.2 自定义 PDO

```C
typedef struct {
    uint16_t controlword;
    uint8_t  mode_of_operation;
    uint8_t  padding;
    int32_t  target_position;
    int32_t  target_velocity;
    int16_t  target_torque;
    int16_t  pos_kp;            /* MIT: 位置刚度（未做） */
    int16_t  vel_kd;            /* MIT: 速度阻尼（未做） */
} motor_rpdo_t;

typedef struct {
    uint16_t statusword;
    uint8_t  mode_display;
    uint8_t  fault_code;
    int32_t  actual_position;
    int32_t  actual_velocity;
    int16_t  actual_torque;
    int16_t  dc_link_voltage;
} motor_tpdo_t;
```

MIT 控制 1 kHz：RPDO + TPDO ≈ 36B。CAN FD 一收一发约占 1 kHz 周期两成量级。OTA：一帧一 ACK，防 FIFO 溢出。

## 六、调试遥测系统

### 6.1 设计方案

```Plaintext
FOC ISR (20kHz, prio 0):
  批量写入变量 → 三缓冲 → 填满 → READY
2kHz 轮询:
  checkAndSend → LPUART DMA
LPUART DMA:
  后台发送；TC 回调回收缓冲
上位机:
  读帧 → CSV / 画 Bode、阶跃
```

### 6.2 帧格式（示意）

```Plaintext
Header: magic + version + buf_idx + sequence + timestamp
Entry:  var_id(2B) + float(4B)  × N
Footer: CRC16
```

### 6.3 原则

- 产品与联调统一走串口遥测，**不用 RTT**（依赖调试器、暂停风险、闭源）  
- ISR 内只写缓冲，不阻塞发送

## 七、RTOS 角色

**原则**：RTOS 只做辅助。硬实时在裸机中断完成。

```Plaintext
中断优先级 (数字越小越高):
  TIM_FOC (20kHz):     prio 0
  ADC 注入完成:        prio 1
  TIM_SPEED (2kHz):    prio 2
  FDCAN RX:            prio 3
  UART / DMA TC:       prio 4
  TIM_BASE (RTOS tick): prio 5

RTOS 任务（示意）:
  Task_CANopenProcess / Task_CLI / Task_OTA / Task_OLED / Task_LED / Task_Logger
```

**禁止**：RTOS 任务碰 FOC ISR、TIM CCR、热路径数据锁。

## 八、状态机设计

### 8.1 两层状态机

```Plaintext
大状态机: IDLE ⇄ SETUP ⇄ CALIBRATION ⇄ TEST ⇄ ENABLED
          ↓                              ↓
        FAULT ←──────────────────────────┘
          ↓
        EMERGENCY

小状态机 (仅 ENABLED): PP / PV / CSP / CSV / CT / HM
  用 C enum + switch
```

### 8.2 事件 / 时间分离

- 事件响应层：只写数据，不改状态  
- 条件检查层（如 2 kHz）：判断并执行转移  
- 行为执行层：只管计算  

### 8.3 共享总线（若有 SPI Flash / 第二编码器）

IDLE/SETUP/CALIBRATION → 任务侧；ENABLED → FOC ISR 独占，任务不得争抢。

## 九、故障诊断

### 9.1 错误码

```C
/* 0xTTSSCCCC */
enum {
    ERR_MOTOR_A_OVERCURRENT   = 0x01000001u,
    ERR_MOTOR_A_OVERTEMP      = 0x01000002u,
    ERR_MOTOR_A_FOLLOWING_ERR = 0x01000003u,
    ERR_MOTOR_A_ENCODER_FAULT = 0x01000004u,
    ERR_POWER_UNDERVOLTAGE    = 0x03000001u,
    ERR_POWER_GATE_FAULT      = 0x03000003u,
    ERR_COMM_CAN_BUSOFF       = 0x04000001u
};
```

### 9.2 记录与上报

ISR 只写 RAM；任务侧 EMCY 上报并可刷 Flash。断电后依赖 EMCY 与下次 POST 读历史。

### 9.3 分级与停机

| 等级 | 响应 | 停机 |
|------|------|------|
| WARNING | 只记录 | 无 |
| RECOVERABLE | 重试计次 | 阻尼停 |
| CRITICAL | 立即停 | 动态刹车 |
| FATAL | 硬件锁死 | 紧急关断 |

停机策略：COAST / DYNAMIC_BRAKE / DAMPED_STOP / EMERGENCY_BRAKE。

3. 死区 LUT  
4. 观测器关键标定量（含 HFI 圆心类零点，若保留 HFI）

## 二十一、后续路线

面向当前仓库，按优先级：

1. **收口无感**：SMO / HFI **产品签收**，或明确裁剪只保留一条路径  
2. **ESO**：速度环扰动观测 + 指令处理扩展点 A（`cmd_proc_ops`）  
3. **自整定流水线**：把手调 PI / 电气参数 / 死区 / 关键观测标定量变成可复现流程（辨识 → 写回）  
4. **关节电机移植**：抽干净 profile + 板级适配，验证同算法异电机；通信域可裁剪  

并行约束：有感三环基线不回退；新增策略尽量新文件 + 宏/profile，少改热路径骨架。

---

## 二十二、维护纪律

1. ops / 公共头一旦定义，不轻改签名；扩充用新 ops 版本或新文件  
2. 新增策略 = 新增 `.c` + 宏/profile 选择，避免在热路径堆 `if (type == ...)`  
3. `motor_core_tick()` 只调 ops，不引入具体观测器类型判断  
4. 函数宜短；热路径禁止阻塞与动态分配  
5. 增量验证：每模块改动后 Keil 编译至 `0 Error(s)`

## 二十三、架构评估

| 维度 | 评分 | 说明 |
|------|------|------|
| 分层清晰度 | 9/10 | 五层单向依赖 + 两域解耦 |
| 扩展性 | 8/10 | C ops + 宏/profile |
| 可维护性 | 8/10 | 全 C，单人可控；profile 需纪律 |
| 可移植性 | 8/10 | 关节/异板靠解耦 + profile（目标） |
| 过度设计 | 2/10 | 无注册中心 / 动态分配 / 多层继承 |
| 现状完成度 | 6/10 | 有感与多算法路径已打通；ESO/自整定/无感签收仍缺口 |
| 产品化程度 | 7/10 | 遥测/辨识强；POST/CANopen/OTA 未全落地 |
| CANopen 兼容性 | 7/10 | 301 骨架 + 402 按需（目标） |

**结论**：框架定为 **全 C、可迁移到关节电机、参数自整定导向**。两域解耦与五层依赖是骨架；扩展点用 **ops / profile**。有感链路与多数算法路径已打通，但 **SMO/HFI 产品签收、ESO、系统化自整定** 仍是明确缺口。160 MHz 上 20 kHz 热路径开销目标仍 &lt; 10% CPU。
