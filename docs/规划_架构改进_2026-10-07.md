## 0. 一页话

1. **PWM 这条链其实已经"薄到可以换"**：`platform/pwm_port_stm32g4_reg.c` 只有 **80 行**，`set_duty3` 实现是 3 行寄存器写。**但 `motor/` 与 `cal/` 绕过了它** —— 契约在，调用链没走。**这就是"最后一米"。**

3. **硬件 / 实验 / 铭牌是三个命名空间、一个模式**（变化频率差三个数量级，不能合成一张表）。
4. **刀序**：`R1a → R1b → R2 → 回调搬出 → 中断优先级集中 → E3-mini`；**HRTIM 只留接口，不写 backend**（板子未到）。

## 3. 目标形状：三个命名空间 + 一个模式

### 3.1 共用的"形"

```
1) ops：函数指针表 + self/hw 指针
2) const 描述：static const 初始化器，零解析，值内联
3) 选择：一个 id / 一个索引 → 取到描述
```

### 3.2 三张表（**变化频率差三个数量级，禁止合并**）

| 命名空间 | 描述什么 | 何时变 | 生命周期 | 消费者 |
|---|---|---|---|---|
| **硬件** `*_board_desc_t` | 存在什么（外设/通道/引脚/周期） | 换板（月级） | **全程 const** | 端口 backend / `bridge_cubemx.c` |
| **实验** `exp_def_t` / `exp_seg_t` | 做什么时序 | 每次实验（**秒级**） | 描述 const + **状态 runtime** | **2 kHz 外环执行器** |
| **铭牌** `motor_cfg_t` | 参数是多少（R/Ld/Lq/ψf/极对数/Kt） | 换电机（周级） | const 或 NVM 只读 | 算法（只读） |

```c
/* ---- 硬件：全程 const ---- */
static const pwm_board_desc_t s_m1_pwm = {
    .ops        = &pwm_port_ops_stm32g4_reg,   /* ← 换 HRTIM 只改这一行 */
    .hw         = &htim8,
    .ch_map     = {0u, 1u, 2u},                /* ← 解 G6 */
    .arr_counts = M1_PWM_ARR_COUNTS,           /* ← 解 G5 */
};

/* ---- 实验：描述 const + 状态 runtime ---- */
static const exp_seg_t s_speed_step_seg[] = { /* 段表 */ };
static const exp_def_t *const g_experiments[] = { /* 注册表 */ };
/* 可变状态（第几段 / A 还是 B）放 ctx，不在这里 */

/* ---- 铭牌：const 或 NVM 只读 ---- */
static const motor_cfg_t s_m1_motor = {
    .rs = M1_RS_OHM, .ld = M1_LD_H, .lq = M1_LQ_H, .pole_pairs = 7u,
};
```

#### 3.2.1 板级描述：**字段清单（含单位）** —— 动手前先看这张

**判据**：一个字段是否进描述表，只看**它在两块板之间会不会不同**。

| 字段 | 单位 | 换板 | 换 MCU | 换外设类型 | 换编码器 | 换功率级 |
|---|---|---|---|---|---|---|
| `ops`（实现指针） | — | | | **✓** | ✓ | |
| `hw`（句柄） | — | ✓ | ✓ | ✓ | ✓ | |
| `ch_map[3]`（逻辑相 → 物理通道） | — | ✓ | | ✓ | | |
| `ch_polarity[3]` / `complementary` | — | ✓ | | ✓ | | |
| `arr_counts`（**计数，不是时间**） | count | ✓ | | ✓ | | |
| `ctrl_ts_ns`（控制节拍） | ns | ✓ | **✓** | | | |
| `deadtime_prog_ns`（**编程**死区 → 定时器） | ns | ✓ | | ✓ | | ✓ |
| `deadtime_eff_ns`（**有效**死区，含驱动+MOS） | ns | ✓ | | | | **✓** |
| `adc_trig_src`（触发链） | — | ✓ | | **✓** | | |
| ADC：`inj_rank[3]` / `scale[3]` / `offset[3]` | — / A per LSB / LSB | ✓ | | ✓ | | |
| 编码器：`word_bits` / `cpr` / `unwrap` | bit / count | ✓ | | | **✓** | |
| 中断优先级表 `{irqn, preempt, sub}[]` | — | ✓ | **✓** | ✓ | | |

**落地状态（2026-10-07 实测）**：`pwm_port_t` 只落了 **`ch_map` + `arr_counts`** 两项；其余**待补** —— 且**必须先等 PWM 那张烧过一次、验过形状**，再照它复制到 ADC / 编码器 / 时间。

**五类禁止**（`hw/board` 里不许出现）

| # | 禁止 | 为什么 | 当前处置 |
|---|---|---|---|
| **1** | **芯片泄漏进契约**：`encoder_spi_bus_ops_t` 的 `dma_ll_rx/tx_ch`(`uint32_t`)、`cs_port`+`cs_pin`、`start_word(...const uint16_t*)` 硬编码 16-bit | 换厂商 / 换编码器时**契约本身**要改 | **只做"注释中立化"**（等第二块板才实质改） |
| **2** | **VESC 式四混编**：标识 / 能力宏 / 脚位 / **动作** 塞同一处 | **动作进 `ops`，数据进 `desc`** | 现有 ops 已分开，保持 |
| **3** | **运行时解析 / 引用别的节点** | 伪 DT 三约束（`const` 初始化器 / 零解析 / **值内联禁止引用**） | — |
| **4** | **电机铭牌**（R / Ld / Lq / ψf / 极对数 / Kt） | 变化频率差**三个数量级** | 另开 `motor_cfg_t` |
| **5** | **实验开关**（前馈 / ESO / 角源）与**策略** | **秒级**变化 | 归 `ctx` 位 / 实验表 |


> **同名待定**（见 §9）：`pwm_board_desc_t` / `exp_def_t` / `motor_cfg_t` 三个名字与 `board` 存放位置，等主人确认后统一。

### 3.3 伪设备树：三条约束（与"真 DT"的分界）

| # | 约束 | 理由 |
|---|---|---|
| **1** | **静态 `const` 初始化器** | 编译器查类型；链接器排布；零运行时开销 |
| **2** | **零解析**（无字符串匹配 / 无查找 / 无分配） | 固件**按板编译**，解析是纯开销；且本工程 **0 动态内存** |
| **3** | **值内联，禁止引用** | ★ **这条是"伪"和"真"的分界线** |

```c
/* ✅ 允许：值内联 */
.ch_map = {0u, 1u, 2u},

/* ❌ 禁止：引用 + 查找（一这么做就上了解析的贼船） */
.adc = node_lookup("adc2"),
.pwm = &node_by_phandle(0x17),
```

**判据一句话**：**允许"一块板 = 一个 const 描述表"；禁止"节点 + 节点之间的引用关系"。** 前者是数据，后者需要解析器。

### 3.4 依赖方向（**单向，破了就回到"三个职责一个开关"**）

```
exp  ──只读──▶  hw/board  ──▶  platform  ──▶  HAL
 │
 └──只读──▶  motor_cfg
```

| 允许 | 禁止 |
|---|---|
| 实验**读**硬件状态（"现在给角源是谁"） | **硬件层认识实验**（`platform/` 里出现 `exp_`） |
| 算法**读**铭牌 | 铭牌里塞实验开关 |
| 实验描述**引用** ops 表 | 实验描述**引用**硬件节点（→ 又回到解析） |

## 6. HRTIM 接入清单（**板子未到，现在只留接口**）

**现在做**：§5 的刀 1~5（= 把接缝真的接上）。**做完之后，"换 HRTIM" = 改一行 `.ops` + 新写一个 backend。**

**不做**：❌ 不写 `pwm_port_stm32g4_hrtim.c`；❌ **连空文件都不建**（避免死文件堆积——GATE 分支就是这么长出来的）；❌ 不重标死区。

**板子回来后的 7 步**：

| # | 动作 | 注意 |
|---|---|---|
| 1 | CubeMX 配 HRTIM：时基、三相输出、死区寄存器、与 ADC 的触发连接 | HRTIM 是**高分辨率**定时器，周期寄存器语义与 TIM 不同 |
| 2 | 新写 `platform/pwm_port_stm32g4_hrtim.c`（~80~150 行） | 只实现 `set_duty3` / `enable` / `disable` |
| 3 | 板级描述改一行：`.ops = &pwm_port_ops_stm32g4_hrtim` | **J2 的兑现点** |
| 4 | 确认 `adc_foc_port` backend 无 TIM 假设 | 触发链变了（TIM8_CH4 → HRTIM） |
| 5 | 中断优先级重排 | 已集中在 `config/`，改一处 |
| 6 | ★ **有效死区重标** | `M1_DEADTIME_NS = 591` 是 **TIM 路径**的**有效死区**（编程 100 ns + 驱动/MOS 延时）→ **HRTIM 不成立**，必须重测；否则死区补偿全错 |
| 7 | 验收 | **主回归门 141（插着编码器）** + **电流环 Bode 复现**（PWM 到 CCR 的路径变了） |

### 11.1 ★ 交叉约定（**必须记住，否则将来会白干**）
