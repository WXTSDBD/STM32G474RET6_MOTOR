# 命令纪律（硬约束，优先级最高）

> 宿主环境：**Windows + PowerShell**。
> 违反以下规则的后果已实际发生过：机器卡顿、Keil 多实例编译冲突、产物污染。

## 1. 工具怎么选：专用工具优先，shell 兜底

Cline 给你四个入口，**别把所有事都塞给 `run_commands`**：

| 想干什么 | 用哪个 | 别用 |
|---------|--------|------|
| 找代码 / 找符号 / 找字符串 | **`search_codebase`**（一次可传多个 pattern） | `run_commands` 里跑 `Get-ChildItem` |
| 读文件内容 | **`read_files`**（长文件用 `start_line` / `end_line` 开窗） | `run_commands` 里跑 `Get-Content` 整个文件 |
| 改文件 | **`editor`** | `Set-Content` / `echo >` |
| 编译 / 跑脚本 / git 查询 | `run_commands` ✅ | — |

为什么：`run_commands` 一次只能跑一条（或几条）命令，**一条命令返回一大堆没人筛过的文本**；
`search_codebase` / `read_files` 返回的是**已经定位好的结果**，一轮拿到的东西多得多。

> 实测教训：某轮任务 271 次工具调用里，`run_commands` 119 次，
> `search_codebase` 只有 2 次（都在开场 3 分钟内，之后再没用过）。
> 结果：193 条命令、并发 7 个终端、机器卡顿、多花几十轮。

## 2. 搜索：一律用 `rg`，禁止递归扫树

- **禁止**：用 `Get-ChildItem -Recurse` / `dir /s` / `find .` 来找文件或找内容。
- **必须**：优先 `search_codebase`；实在要用 shell 才用 `rg`（ripgrep）。
  - 若 `rg` 报「无法识别」，用绝对路径：`D:\cursor\resources\app\node_modules\@vscode\ripgrep\bin\rg.exe`（Cursor 自带 ripgrep 15.1，已验证可跑）。

```powershell
# shell 兜底时
rg -n "foc_pi_step" -g "*.c" -g "*.h" motor/ platform/
rg --files -g "*.h" motor/
```

原因：本仓库全树 **17,000+ 文件 / 33 GB**（含大量构建产物）。
`Get-ChildItem -Recurse` 会遍历全部，PowerShell 里再叠 `Sort-Object` / `Select-Object`，
是**本机最慢的搜索方式**。

例外：只在明确的小目录（`motor/`、`config/`、`docs/`）且只列一层时，允许
`Get-ChildItem -LiteralPath <明确路径> -File`，禁止 `-Recurse`。

## 3. 一次只跑一个终端命令

- **禁止**：在一次工具调用里并行发多条命令。历史上出现过 **7 个终端同时递归扫树**。
- **必须**：一条命令 → 读结果 → 再决定下一条。
- 除非用户明确要求并发，否则串行。
- 需要一次问多件事 → 那说明你该用 `search_codebase`（它支持多 pattern），不是发多条 shell。

## 4. 命令必须短、必须能结束

- **禁止**：预计超过 60 秒的命令。
- **禁止**：`Start-Process` 不带 `-Wait`（会留下孤儿进程）。
- **禁止**：`python -c "..."` 长内联脚本。PowerShell 引号转义会吃掉内容，
  且每次冷启动 numpy 很慢。
  → 写成文件：通用工具放 `tools/`，分析脚本放当天 `VOFA+CSV/<YYYYMMDD>/_analyze_*.py`，再执行。
- 一条命令正文超过 3 行 → 写成脚本文件再跑。

## 5. 禁止重复劳动

- 同一份信息（目录树、文件清单、`git status`）**不要连续查第二遍**。
- 上一轮已拿到的输出直接用，不要为"再确认一下"重跑。
- 你记不住上一轮的结果 → 那就把它**写进文件**（见 `01-工作方式.md` 第 9 条）。

## 6. Keil 编译：一次只准一个实例

- 编译前先查有没有残留：
  `Get-Process UV4 -ErrorAction SilentlyContinue`
- 有残留 → 先报告用户，**不要直接再起一个**。历史上曾连续拉起 8 次 UV4。
- 默认用 `-b`（增量），除非用户要求 `-r`（全量重建）。
- **禁止并行编译**，禁止 `-j0`。
- 细节见 `10-交付前编译.md`。

## 7. 危险命令一律先问

执行前**必须**征得用户明确同意：

`Remove-Item` / `rm` / `del` / `Move-Item` 会覆盖目标 /
`git add|commit|reset|checkout|clean|stash|push|mv` /
任何改写 `Core/`、`MDK-ARM/` 下生成物的操作。

只读查询（`git status` / `diff` / `log` / `ls-files`）不受限。

## 8. 没有产物就别写分析脚本

先交付可烧录包，等台架跑完、CSV 回到本地，再写分析脚本。
不要先堆脚本、不要假设马上有 CSV。
