## §0 一句话

把"**ISR 每拍往 `dbg` 里搬值**"改成"**打包时按需从状态里读值**"，
顺手把 `19 个 M1_VOFA_* 宏 + 6 个 #elif` 压成**一张 12 行 const 表** —— **一次解决两个问题**。

---

## §1 先拆：这是两个不同的问题（原计划只解决了后一个）

| | **问题 A** | **问题 B** |
|---|---|---|
| 名称 | **热路径每拍写入** | **通道表硬编码** |
| 现象 | ISR 里 `dbg.x = v`（140+ 处），`volatile` 全局 | 19 个 `M1_VOFA_*` 宏 + 6 个 `#elif` 选布局 |
| 代价 | 20 kHz 每拍多写、编译器**一点都优化不掉**（`volatile`） | **换看什么量 = 重编 + 重烧 + 可能重录金样** |
| 原计划（产品定完 → 整表 → 动态切换） | ❌ **不解决** | ✅ **解决** |

> 【事实】你们文档里记过一句：**"删通道 = 重录金样"** —— 那正是问题 B 的代价。

## §3 目标形态：一张表 + 一个 layout 索引

```
现在：ISR 每拍写 dbg.x = v ──→ packer 读 dbg.x ──→ 打包 ──→ DMA
目标：ISR 不写        ──→ packer 调 get_x()（直接读 ctx / 静态状态）──→ 打包 ──→ DMA
```

```c
/* 遥测通道描述：名字 + 取值函数 */
typedef struct {
    const char *name;
    float (*get)(const motor_context_t *ctx);
} telem_ch_t;

#define TELEM_LAYOUT_UNIFIED   0u
#define TELEM_LAYOUT_SIGNOFF   1u
#define TELEM_LAYOUT_HFI       2u
/* … */

static const telem_ch_t s_layout_signoff[12] = {
    { "ia",        tl_ia        },
    { "ib",        tl_ib        },
    { "ic",        tl_ic        },
    { "iq",        tl_iq        },
    { "theta_fb",  tl_theta_fb  },
    { "theta_mech",tl_theta_mech},
    { "theta_ref", tl_theta_ref },
    { "theta_err", tl_theta_err },
    { "omega_pll", tl_omega_pll },
    { "omega_ref", tl_omega_ref },
    { "iq_ref",    tl_iq_ref    },
    { "mark",      tl_mark      },
};
```

**一次拿到两个收益**：
- **B**：`19 个宏 + 6 个 #elif` → **一张 const 表 + 一个 layout 索引**（可运行时选）
- **A**：ISR 里那些"把值搬进 `dbg`"的写，**对应的可以删掉**（值本来就在状态里）

## §4 ★ 热路径 141 处写入的普查（这是本方案的关键证据）

把 `motor_current.c` 的 `dbg.` 写按**来源**分成四类（含实测样本）：

| 类 | 含义 | 实测样本 | 处置 |
|---|---|---|---|
| **A · 镜像** | 值本来就在 `s_*` / `ctx` 里，只是被搬进 `dbg` | `:135 dbg.outer_theta_mech_rad = s_theta_mech_rad;`<br>`:137 dbg.outer_omega_mech_rpm = s_speed_fb_rpm;`<br>`:907 dbg.pll_omega_mech_rpm = s_pll_omega_mech_rpm;`<br>`:1047-1049 dbg.foc_ia/ib/ic = ia/ib/ic;`<br>`:889 dbg.enc_raw = (float)enc_raw;` | ✅ **getter 直接读 → 写入可删** |
| **B · ISR 局部中间量** | 由 ISR 内局部变量算出，没存下来 | `:334 dbg.id_acdc = (id_mean > 0.05f) ? (id_pp / (2.0f * id_mean)) : id_pp;` | ⚠️ 三选一：进 `ctx` / getter 重算 / **放弃该通道** |
| **C · 复位** | 为了让上次的值不残留而清零 | `:713-717 dbg.pll_omega_mech_rpm = 0.0f; …`<br>`:1112/:1497 dbg.outer_omega_ref = 0.0f;` | ✅ **表化后自然消失**（不再有"残留"概念） |
| **D · 打点** | 段号标记（已符号化为 `EXP_MARK_*`） | `:473 dbg.open_seq_phase = 60u;`<br>`:1326 dbg.open_seq_phase = EXP_MARK_IF_OBS_ANGLE_ONLY;` | ✅ **保留**（是判据输入，不是遥测） |

> **读法**：141 处里，**A + C 两类占多数，且都能被"表化"消掉**；
> **B 类是少数**，需要逐条决定；
> **D 类必须留**（`exp_mark` 的段号是 PC 判据的依据）。

### 一个强证据：**P3 签收档的 12 个通道，一个都不需要每拍写**

`app_uart_dma_debug.c:254-272` 的 `M1_VOFA_SIGNOFF_CH` 分支：

```
ia, ib, ic, iq, theta_fb, theta_mech, theta_ref, theta_err,
omega_pll, omega_ref, iq_ref, open_seq_phase
```

→ **这 12 个全是"已经在状态里的量"**（镜像 + 打点），**没有一个是 B 类局部量**。
→ 所以 **T-1 的 12ch 表化对签收档是完全可行的**。

## §5 三个坑（必须提前处置，否则表化会引出新问题）

| # | 坑 | 说明 | 处置 |
|---|---|---|---|
| **1** | **撕裂读（tearing）** | 多字节 `float` 在 ISR 更新时被读走"半新半旧" | **保持现有快照模式**：某个 tick 一次性拷进 `snap[]`，之后只读 `snap`。**禁止 getter 直接读 ISR 正在改的量** |
| **2** | **ISR 局部量读不到**（B 类） | 中间量没存下来 | 三选一：① 存进 `ctx`（加状态，最干净）② getter 里**重算**（如 `sin/cos`，便宜）③ **放弃该通道**（不常用就别留） |
| **3** | ⚠️ **`dbg` 不只给遥测用** | `dbg_monitor.h` 被 **14 处** include（含 `deadband_*` / `ident_*` / `foc_svpwm`）；`ident`/`deadband` 拿它当**调试出口** | **不要删 `dbg`** —— 只把"**纯为遥测**"的写入迁走；`dbg` 降级为"探索类实验的残留观测" |

> 坑 3 决定本方案的**边界**：目标是"**分家**"，不是"消灭 `dbg`"。
> 若按"删 dbg"做，会牵连 14 个 include 它的文件 —— **那是另一个量级的工程**。

## §6 三步（T-1 就能拿到 80%）

| 步 | 做什么 | 收益 | 动 ISR？ | 档位 | 判据 |
|---|---|---|---|---|---|
| **T-1** ⭐ | **12ch 表化** + **运行时选 layout** + **帧头带 `layout_id`** | **换看什么量不再重编、不再重录金样** | ❌ **不动** | 档 2（只改打包侧） | 同一 layout 下 12 通道**逐通道等价**（金样 CSV 同结果） |
| **T-2** | 把 12 个 getter 指向 `ctx`/静态状态，**删掉对应的 A/C 类 `dbg.` 写** | **热路径写入减少**（从 141 起降） | ✅ 动 | 档 2（**要烧**） | 主回归门（**GATE 141 插编码器**）+ P3 金样 |
| **T-3** | 全表化（161 字段逐步迁）+ 上位机 UI | 你说的"**软件示波器长期使用**" | ✅ | 长期 | 每迁一批一个回归 |

**★ T-1 是性价比最高的一步**：**不碰 ISR**，却直接废掉"删通道 = 重录金样"这条。

## §7 T-1 规格（可直接施工）

| 项 | 规格 |
|---|---|
| **表位置** | 新文件 `debug/telem_table.c`（表 + getter）+ `debug/telem_table.h`（类型 + layout id） |
| **表元素** | `{ const char *name; float (*get)(const motor_context_t *ctx); }`，12 项/layout |
| **layout 选择** | `M1_TELEM_LAYOUT`（编译期默认，等价于现在的宏）→ **运行时** `telem_set_layout(id)` 可切 |
| **帧头 `layout_id`** | **默认关**（`TELEM_FRAME_LAYOUT_ID=0`）。占 +4 B/帧、VOFA 多一路；运行时切 layout **未用上**时无收益。<br>真要运行时切表时再改为 1，并同步 VOFA 通道数与 `tools/` |
| **快照** | 沿用 `telem_refresh_buf_snapshot()`；getter 在**快照点**调用，结果写进 `snap[]` |
| **保护** | `telem_set_layout` 越界 → 落回默认 layout（不空指针） |
| **不动** | `dbg` 结构、ISR、`M1_TELEM_BRINGUP_K`（仍 12） |

**施工前置（约半小时的只读普查）**：逐通道确认**取值来源**
```
每通道一行：name | 现在的 dbg 来源 | 真实来源（ctx->x / motor_outer_loop 的 s_y / ISR 局部）
```
→ 只有"A 类 / C 类"的通道能进 T-1 表；"B 类"通道**先标出、暂不迁**。

**T-1 验收**：
1. 编一次 → `Code/RO/RW/ZI` 四数变化可解释（**新增表 + getter**，属档 2）；
2. 同一 layout 下，**12 通道逐通道与改前等价**（同一段实验的 CSV 对比）；
3. 默认 12ch 帧与改前签收语义等价；若打开 `TELEM_FRAME_LAYOUT_ID` 则脚本须能剥 id；
4. `quickcheck` 0 error / 0 warning；Keil **0 Error(s) / 0 Warning(s)**。

## §8 触发条件与"不做"

### 什么时候做

| 触发 | 说明 |
|---|---|
| ★ **新编码器 / CBT6 真要加通道**（如 `enc_raw`、θ 误差） | **这就是触发点** —— 现在每加一个通道都是"重编 + 重烧 + 可能重录金样"；**T-1 提前做正好省下这些** |
| 要把 VOFA 当**长期示波器**用 | T-1 + T-3 的正当理由 |

### 明确不做

| ❌ | 理由 |
|---|---|
| **现在做 T-3（全表化 + UI）** | 161 字段逐步迁，且**要先有 UI 才有收益**；没有 UI，表化只是重构 |
| **删 `dbg`** | 被 14 处 include（含算法层），是另一个量级 |
| **改 `M1_TELEM_BRINGUP_K`** | 会同时打击 12ch 判据、金样、PC 脚本 —— **本方案明确不动它** |
| **在 getter 里直接读 ISR 正在改的量** | 撕裂读；必须走快照点 |
