## 分析结论

### Phase 1（有电，0-14.4s）——电流环工作正常

**电流环的软件链路（Clarke/Park/PI/SVPWM/编码器/死区补偿/相序绑定/CORDIC）全部验证通过。** Iq=1.0A 跟踪完美（均值 0.999A，σ=0.103A），Uq 随转速自然爬升且从未触顶，电机加速到 730 RPM。不存在角度偏差、不存在限幅瓶颈、不存在积分器 bug。

唯一的问题是**启动**：前 3 秒 Iq=1.0A 但电机仅 0.2 RPM——齿槽转矩挡住了。之后转子越过齿槽峰值后正常加速。这和主人的描述「0.6-0.9A 不转、1.0A 手拨才转」一致——0.068 Nm 在临界线上。

### Phase 2（断电，14.4-37.2s）——预期行为，非 bug

所有 Phase 2 的「异常」（Uq=6V 饱和、Iq 下降/变负、反向滑行）都是断电后的预期系统响应。PI 不知道母线没了——它在做它该做的事。需要的是**母线电压检测 + 故障时关闭 PI**——而不是修改 PI 算法。

### 排名（按「需要主人动手」排序）

1. **候选 B（断电后无保护）—— 90/100**：解释了主人最困惑的「Iq 变负」现象。改动方向：加母线电压检测/故障处理——不是修 PI。
2. **候选 A（齿槽/静摩擦）—— 85/100**：解释了启动困难。改动方向：加启动策略（对齐+开环拖动/Iq boost）——也不需要动 PI。

### ④号决策的输入摘要

Phase 1 数据证明电流环软件链路完整正确。剩余两个问题：(1) 启动阶段齿槽转矩导致 Iq=1A 时仍有 3s 延迟或需手拨——需要启动策略（对齐+开环拖动或 Iq boost），非软件 bug；(2) 断电后 PI 无保护——需要母线电压丢失检测+故障关断。两个都是**系统层面的补充**，不是**算法层面的修复**。PI 参数、角度跟踪、死区补偿——不需改动。
