# 交付前编译（硬约束）

来源：`.cursor/rules/keil-build-verify.mdc`（Cursor 侧的 alwaysApply 规则）。

**凡改了会进 MDK 的代码或配置，在交给人类（说「做完了」「可烧录」「下一步」）之前，
Agent 必须自己跑一遍 Keil 编译，结果 `0 Error(s)` 且 `0 Warning(s)`。**

- **禁止**：只改代码不编译就交付；假设「应该能过」；让用户去编译找错；把 Warning 留给用户。
- **必须**：本机执行下方命令，读 `rebuild_log.txt` **末尾**汇总；有 Error/Warning 就自己修到 0/0 再回复。
- **固定工作流**：改代码（按注释规范）→ 自己编到 0/0 → **先交付可烧录包**
  （`MDK-ARM/_pkg/<日期>_<实验名>/`：hex + rebuild_log + size + sha256 + bringup/profile 快照）
  → 用户上台架跑 → 回 CSV 后才写分析脚本。

**顺序硬约束**：先给 Keil 可烧录产物，再写分析脚本；不许先堆脚本。
**不要催结果、不要假设立刻有 CSV**（台架实验有等待期）。

仅改 `tools/*.py`、`docs/`、`.cursor/` 且未动固件时，可跳过 Keil。

## 命令（PowerShell）

工程文件：`D:\stm32\STM32G474RET6_MOTOR\MDK-ARM\STM32G474RET6_MOTOR.uvprojx`

```powershell
Set-Location "D:\stm32\STM32G474RET6_MOTOR\MDK-ARM"
Start-Process -FilePath "D:\keil5\UV4\UV4.exe" `
  -ArgumentList '-b','D:\stm32\STM32G474RET6_MOTOR\MDK-ARM\STM32G474RET6_MOTOR.uvprojx','-o','D:\stm32\STM32G474RET6_MOTOR\MDK-ARM\rebuild_log.txt' `
  -Wait -NoNewWindow
Get-Content "D:\stm32\STM32G474RET6_MOTOR\MDK-ARM\rebuild_log.txt" -Tail 5
```

小改动用 `-b`（Build）；需全量才用 `-r`（Rebuild）。**勿用 `-j0` 并行。**

⚠️ 命令纪律补充：执行前先 `Get-Process UV4 -ErrorAction SilentlyContinue` 确认无残留实例。

## 判定与固件范围

- 末尾须含 `0 Error(s)` **且** `0 Warning(s)`（以末尾汇总为准，勿被中间 ArmClang stderr 误导）。
- 固件变更范围：`Core/`、`motor/`、`config/`、`debug/`、`Drivers/`（业务侧）、`MDK-ARM/`，
  以及会触发 `#error` 的宏。

## 回复格式

交付时写明例如：`Keil Rebuild: 0 Error(s), N Warning(s)`。未通过不得声称任务完成。
