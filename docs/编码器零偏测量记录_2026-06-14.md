## 1. 问题是什么

`as5047_spi1.add` 参与 `encoder_get_theta_el()`，决定 Park 变换用的电角是否与转子磁场对齐。

| 状态 | 现象 |
|------|------|
| 对齐 | 电流主要在 **Iq**，**Id ≈ 0**，力矩正常 |
| 未对齐 | **Id 大**（可与 Iq 同量级正弦耦合），力矩差、有时像抱闸 |

开环 Uq 固定时，工程上曾出现 **Id ≈ Iq**，说明写死的 `add` 或自动标定结果不可用。

| 项 | 内容 |

| 遥测 | VOFA ch0=Iq、ch1=Id；**6-14 改 ch2=`raw`、ch3=`add`**（`app_uart_dma_debug.c`） |

### 2.2 测量与数据

| 数据文件 | 内容 |
|----------|------|
| `vofa+202606141811.csv` | 手动扫 **add 0～6.2**（步进 0.1），ch2 仍为 0，**不可用于转速** |
| `vofa+202606141928.csv` | 同上扫频，**ch2=raw**，可算机械转速；约 28 个 add 点、363 s |

> **采样条件：** `Uq=2` 开环、TIM8 JEOC 20 kHz、遥测 decimation=100 → 有效采样 200 Hz。raw 为 14-bit（0~16383），一圈 = 16384 counts。机械转速 = Δraw / Δt / 16384 × 60 rpm。

### 2.3 测量方法演进（当日共识）

1. **锁转子** → 得到中间读数约 **3.45 rad**（带歧义，非最终运行值）  
2. 早期尝试：全扫 add + 看 **Id/Iq** 或 **mean |Id|** → **误导**（见 §3）  
3. 正确开环判据：**固定 Uq**，用 **raw 斜率算机械转速**，转速高 ≈ 对齐好  
4. 几何解释：锁转子值 **± π/2** → 两个候选簇（实测峰在 **~2.1** 与 **~5.1**，两峰相差约 **π**）

## 3. 哪里错了、为什么错

### 3.1 自动锁转子 +「减 π」后直接用 3.x

| 现象 | 锁转子后 `add` 落在 **3.3～3.7**（如 3.45、3.6） |
| 结果 | VOFA 上 **Id 仍大**，电机有时 **难转** |
| 原因 | 3.x 落在两个「转速峰」之间的 **坏区**（与 2.6～4.4 一带一致）；**减 π** 把结果推离真值簇，且 **未解决 ±π/2 歧义** |

### 3.2 用 CSV 的 mean |Id| 选 add（如 5.7）

| 误判 | add=5.7 mean |Id| 最小 → 曾判为「最优」 |
| 实测 | `vofa+202606141928.csv` 中 **5.7 转速 ~20 rpm**，低于峰 **~28 rpm** |
| 原因 | 开环下 **转速随 add 变** → 电流幅值跟着变；\|Id\| 小可能是 **转得慢、没出力**，不是对齐好 |

### 3.3 开环下用 Id/Iq 波形形状选优

| 问题 | 即使 add 正确，开环无 PI，**Id/Iq 仍可能呈正弦**（反电动势） |
| 结论 | 波形形状 **不能** 在开环下区分 2.1 vs 5.1；需 **raw 转速** 或 **闭环 Ud** |

### 3.4 电机不转时段的 Id/Iq

| 现象 | add≈**0**、**~1.25** 时 Iq/Id 几乎不变（std 很小） |
| 含义 | 转子未转，通道上是 **偏置/锁死**，不是 dq 对齐质量 |
| 处理 | 分析时应 **排除** 此类段 |

### 3.5 遥测 RPM 量级错误（他方 AI 曾报 ~2800 rpm）

| 正确 | 200 Hz 采样（`TELEM_BRINGUP_DECIMATION=100` @ 20 kHz），14bit raw：**~26～28 机械 rpm** 为峰 |
| 错误 | 若按 20 kHz 或漏除 16384，会得到 **~100× 偏大** 的 rpm；**排名** 仍可能对，**绝对值** 不可信 |

## 4. 实测结论（`vofa+202606141928.csv`）

### 4.1 转速峰（机械 rpm，由 raw unwrap 估算）

| add (rad) | 约 rpm | raw ticks/s | 备注 |
|-----------|--------|-------------|------|
| **2.1** | **~28.1** | ~7700 | **最高** |
| 2.0～2.3 | ~27～28 | ~7400～7700 | 第一高原 |
| **5.1** | **~28.0** | ~7650 | 次高，与 2.1 差 ~2% |
| 1.4～1.7 | ~20～26 | ~5500～7100 | 可转但非峰 |
| **2.6** | ~7.7 | ~2100 | Id 大，弱转/失步 |
| **4.4** | ~8.2 | ~2250 | Id≈Iq 量级，坏区 |
| **5.8** | ~1.6 | ~440 | 近堵转 |

### 4.2 与锁转子 3.45 rad 的关系

```text
add_lock ≈ 3.45 rad          ← 锁转子直接结果（带歧义）
add_lock − π/2 ≈ 1.88 rad    ← 候选 A → 实测峰 ~2.1
add_lock + π/2 ≈ 5.02 rad    ← 候选 B → 实测峰 ~5.1
两候选相差 π；2.1 与 5.1 亦相差约 π
```

### 4.3 与历史手调 2.1 的关系

早期 `angle_init()` **写死 ~2.1 rad** 属于 **偶然落在正确簇**；本次用 **raw 转速** 独立验证，**数值几乎相同**，但明确了 **为何 3.x 错、5.1 为备选**。

## 5. 当前工程应使用的配置

```c
#define M1_RUN_ENCODER_CAL  0      /* 电流环阶段勿上电覆盖 add */
#define M1_ENCODER_OFFSET_RAD  2.10f
```

`angle_init()` → `as5047_spi1.add = M1_ENCODER_OFFSET_RAD`。

**注意：** 撰写本文时 `main.h` 若仍为扫频试验值（如 6.0f），请改回 **2.10f** 再跑电流环。

## 8. 一句话摘要

**锁转子给出 ~3.45，不是运行 add；真值在 ±π/2 两簇（~2.1 / ~5.1）。开环应用 raw 比转速，不是比 |Id|。当前冻结 2.10 rad 做电流环；出厂自动化以后再实现「锁转子 → 两候选 → 比转速 → NVM」。**
