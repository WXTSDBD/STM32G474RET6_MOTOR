# Port 分层与 20 kHz 热路径边界

来源：`.cursor/rules/port-layer-hot-path.mdc`。

## 分层

- `motor/`：算法与编排，**零 HAL、零 LL、零 `main.h`**。
- `Drivers/`：芯片无关语义（如 `adc_sample.h` 类型 / API，无 HAL）。
- `platform/`：Port 契约头文件（无 HAL）+ 各芯片 backend `.c`（可 HAL / 寄存器 / LL）。
- `board/`：板级实例与 ops 绑定。
- `config/`：`bridge_*` 与 `hal_bridge.h` —— CubeMX HAL 句柄**只从这里**进 board / platform。

## 热路径（20 kHz JEOC 链）

- 允许：直接寄存器访问、`__HAL_*` 等 HAL 宏。
- **禁止**：在 JEOC 链中 `#include` LL 驱动头并调用 LL API。
- LL 仅用于 init、标定阻塞路径、RTOS 任务、编码器 DMA 配置等非实时路径。

## 可移植边界（HAL 类型 vs HAL API）

| 类别 | 例子 | 破坏什么 | 处置 |
|---|---|---|---|
| **HAL 类型** | `TIM_HandleTypeDef*`、`ADC_HandleTypeDef*` | **分层**（`motor/` / `cal/` 契约） | **必须清**；经 `pwm_port_t*` / `void*` / board |
| **HAL API** | `HAL_GetTick`、`HAL_FLASH_*` | **可移植**（换 MCU 要改实现） | 优先换 `time_port_*`；Flash 等厂商必然绑定可留在 `cal/` / `platform/` 并标注 |

不要把「文件里出现 `HAL_` 字符串」一律当破口——注释里的回调名、厂商必然 Flash 路径都不是分层失败。

## 引用

- HAL 句柄：`#include "hal_bridge.h"`（**勿从 `main.h` 拿**）。
- PWM / ADC 热路径：经 `pwm_port_*` / `adc_foc_port_*`。
- 台架开关：`config/bringup_bench.h`（**勿再塞回 `main.h`**）。
