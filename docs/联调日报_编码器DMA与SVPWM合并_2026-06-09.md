# 联调日报：编码器 DMA 与 SVPWM 优化合并（2026-06-09）

> **平台：** STM32G474RET6 @ 160 MHz，Keil AC6，Release **-O2**  
> **控制：** TIM1 20 kHz 周期中断 + FreeRTOS（LPUART 6 Mbps VOFA 遥测）  
> **传感器：** AS5047 @ SPI1，DMA 双帧异步读（encoder v1.0 冻结架构）  
> **执行器：** Ud=0 开环 `Uq=2`，`setPhaseVoltage`（瘦身 SVPWM + CORDIC sincos）  
> **分支：** `feature/uart-dma-telemetry`（encoder DMA）+ `SVPWM_DOWN`（motor_trig / trans diet）手工合并  

---

## 一、今日目标与背景

### 1.1 要达成什么

1. 把 **SPI DMA 编码器**（`enc_m1`、`board_encoder_m1`、LL fast path）与 **优化版 SVPWM**（`bringup/trans.c` + `motor_trig`）合在同一固件里。  
2. 20 kHz 下 **非阻塞读角 + 电机持续转**，VOFA 遥测不拖死 RTOS。  
3. 用 DWT / `g_telem_dbg` 量化 **motor_path_cpu**（TIM1 + SPI DMA ISR，含 kick），对照 **2700 cycle TIM1 硬预算**（见 §三），评估后续 FOC 还能加多少。

### 1.2 合并前两条线的状态

| 分支/快照 | 已有内容 | 缺什么 |
|-----------|----------|--------|
| **encoder 分支** | `Drivers/encoder`、`as5047_async`、LL SPI1、`encoder_kick` @ TIM1 | 仍是旧版/fat `trans.c` 或未接 CORDIC |
| **SVPWM_DOWN** | diet 后 `trans.c`、`motor_trig_cordic`、Cube CORDIC | 无 DMA encoder，TIM1 可能仍阻塞读角 |
| **合并后（今日）** | 两者叠加 | 工程配置、IT 向量、极对数、main 时序需手工对齐 |

### 1.3 合并策略（避免整仓覆盖）

| 操作 | 路径 |
|------|------|
| **可整夹拷贝** | `bringup/trans.c`、`motor_trig*`、`math_tables/`（可选 LUT）、`tools/gen_math_tables_sincos.py` |
| **需手工 merge** | `main.c`（TIM1 回调、极对数）、`stm32g4xx_it.c`（Ch2 ISR）、`uvprojx` **追加** 源文件 |
| **禁止 blind 覆盖** | encoder 分支整仓、完整 `uvprojx`、Cube 生成的 `dma.c` NVIC 语义 |
| **Cube 改动量** | 主要是 **使能 CORDIC**；SPI1 DMA 通道分配保持；Ch2/Ch3 NVIC 可改为不自动生成 ISR |

## 二、性能演进（本会话相关）

| 阶段 | `isr_delta`（约） | 电机 | RTOS/VOFA | 说明 |
|------|-------------------|------|-----------|------|
| 原始 fat SVPWM + fmod/atan2 | **5800～7200** | 可能转 | **`uart_task_loops=0`，VOFA 停** | 2025-06 联调已验证 |
| 去掉 sqrt/atan2，保留 fmod nor | **~2700** | 能转 | **正常**（`acquire_fail=0`） | 历史 **安全线** |
| encoder-only（无 SVPWM） | **~676** | 不驱动 | 正常 | SPI 架构文档 -O2 基线 |
| **今日合并后（-O2，初版）** | **~1315** | **持续转** | **正常** | kick + get_theta_el + CORDIC SVPWM + telem 轻拍 |
| **P0：去 `_normalizeAngle`（-O2）** | **~1200** | **持续转** | **正常** | `add` 并入 `encoder_get_theta_el`；**−115 cycle** |

**关键结论：** 性能大头来自 **SVPWM 数学 diet**（~4000+ cycle 级），不是 CORDIC vs LUT 二选一；encoder DMA 额外约 **~580 cycle/拍**（kick 在 TIM1 内 + DMA 回调）。

## 三、硬预算：2700 cycle 与 RTOS「卡死」

### 3.1 预算定义（本项目实测约束）

| 项目 | 数值 | 说明 |
|------|------|------|
| TIM1 周期 | 50 µs（20 kHz） | |
| 每拍 CPU cycle @ 160 MHz | **8000** | 理论上限 |
| **`isr_delta` 硬预算** | **≤ 2700** | **仅 TIM1 用户段**；超过后 FreeRTOS + 遥测 effectively 卡死 |
| **当前 `isr_delta`** | **~1200**（**≈ 7.5 µs**） | 其中 **~254 已是 SPI kick** |
| **`motor_path_cpu`（TIM1 + SPI DMA ISR）** | **~1515**（**≈ 9.5 µs**） | **= `isr_delta` + `enc_dma_cpu_delta`；FOC 规划基线** |
| 其中 SPI 全路径 | **~581**（**≈ 3.6 µs**） | kick(254) + f1(274) + f2(53)；**已固定，FOC 省不掉** |
| **SVPWM + SPI（CPU 合计）** | **~1450**（**≈ 9.0 µs**） | 见 §3.5；占 50 µs 一拍 **~18%** |
| **FOC 可用余量（TIM1 内）** | **2700 − 1200 ≈ 1500** | 硬限；建议目标 < 2500 留 telem spike |
| **FOC 可用余量（motor_path 总包络）** | **~3200 − 1515 ≈ 1685** | 经验上限，含 SPI 后仍留 RTOS 窗口 |

> **时间换算 @ 160 MHz：** 1 cycle = 6.25 ns，**160 cycle ≈ 1 µs**。

> ⚠️ 文档 [`联调日报_ISR负载与遥测_2025-06-07.md`](./联调日报_ISR负载与遥测_2025-06-07.md) 与 [`完整联调回顾_串口DMA遥测与电机_2025-06-07.md`](./完整联调回顾_串口DMA遥测与电机_2025-06-07.md) 记录：  
> `isr_delta ≈ 2707` 时 `uart_task_loops` 持续增、`dma_start_ok` 正常；  
> `isr_delta ≈ 5800`（fmod nor 开）时 **`uart_task_loops = 0`**、`acquire_fail` 涨、VOFA 停。

### 3.2 SPI / 编码器 CPU 怎么算（必须和 TIM1 分开看清）

AS5047 双帧读（命令 + NOP）每 **20 kHz 完成 1 次**，CPU 分 **三段**，DWT 字段在 `g_telem_dbg`：

| 阶段 | 运行上下文 | Watch 字段 | 典型 cycle | 是否含在 `isr_delta` |
|------|------------|------------|------------|----------------------|
| FRAME1 kick | TIM1 内 `encoder_kick` | `enc_dma_kick_delta` | **~254** | **是** |
| FRAME1 完成回调 | DMA1 Ch2 ISR（prio 2） | `enc_dma_f1_cb_delta` | **~274** | **否** |
| FRAME2 完成回调 | DMA1 Ch2 ISR | `enc_dma_f2_cb_delta` | **~53** | **否** |
| **SPI DMA 回调小计** | | `enc_dma_cpu_delta` (= f1+f2) | **~315** | 否 |
| **SPI 全路径 CPU/拍** | kick + f1 + f2 | （手算或快照相加） | **~581** | 254 在 TIM1 内 |

**推荐每拍合计公式（单核 CPU 加总，@ 20 kHz 读角 + SVPWM 同开）：**

```text
enc_spi_cpu_total  = enc_dma_kick_delta + enc_dma_f1_cb_delta + enc_dma_f2_cb_delta
                   ≈ 254 + 274 + 53 ≈ 581 cycle/拍  ≈ 3.6 µs

motor_path_cpu     = isr_delta + enc_dma_cpu_delta
                   ≈ 1200 + 315 ≈ 1515 cycle/拍  ≈ 9.5 µs

isr_non_spi         = isr_delta − enc_dma_kick_delta
                   ≈ 1200 − 254 ≈ 946 cycle/拍   （SVPWM + 读角 + telem + DWT）
```

**不要和 `enc_dma_seq_delta`（~1972）相加：** 那是 kick→F2 的 **墙钟**（≈12.3 µs，含 SPI 硬件移位），大部分时间在等外设，**不是 CPU**。

**与 TIM1 的并行关系：** kick 之后 SPI 硬件与 `setPhaseVoltage` **并行**；DMA 回调通常在 **TIM1 退出后**（prio 2）执行。单核上 **cycle 仍累加**，只是 wall time 重叠。

### 3.3 硬预算：2700 cycle 与 RTOS「卡死」

| 项目 | 数值 | 说明 |
|------|------|------|
| TIM1 周期 | 50 µs（20 kHz） | |
| 每拍 CPU cycle @ 160 MHz | **8000** | 理论上限 |
| **`isr_delta` 硬预算** | **≤ 2700** | **仅指 TIM1 用户段**；超过后 FreeRTOS + 遥测 effectively 卡死 |
| 当前 `isr_delta` | **~1200** | 其中 **~254 已是 SPI kick** |
| **当前 motor_path_cpu（TIM1+SPI DMA ISR）** | **~1515** | **= isr_delta + enc_dma_cpu_delta** |
| 其中 SPI 占 motor_path | **~581** | **≈ 38%** 的 motor_path |
| 其中 SVPWM+其它占 motor_path | **~946** | `isr_delta` 去掉 kick |

> ⚠️ [`联调日报_ISR负载与遥测_2025-06-07.md`](./联调日报_ISR负载与遥测_2025-06-07.md)：  
> `isr_delta ≈ 2707` 时 RTOS/VOFA 正常；`isr_delta ≈ 5800`（fmod nor）时 **`uart_task_loops = 0`**。  
> 该 **2700 来自 TIM1 独占测量**；引入 DMA 后 **还需加上 ~315/拍的 DMA ISR**，RTOS 窗口更紧。

**为什么超过 2700（仅看 TIM1）RTOS 会卡：**

```text
TIM1 ISR (prio 1) 过长
  → 50µs 内 CPU 大量时间在 TIM1，调度窗口被挤没
  → UART_DMA_DEBUG 任务得不到运行（uart_task_loops 不涨或归零）
  → VOFA 停更；电机 TIM1 可能仍在跑
```

**DMA ISR 的额外影响：** 每拍再占 **~315 cycle**（prio 2），与 TIM1 **串行占用同一 CPU**，进一步压缩 RTOS 时间片。  
因此评估 FOC 余量时 **不能只看 `isr_delta`**，必须 **把 SPI DMA 回调算进 motor_path_cpu**。

**FOC 联调建议：**

| 指标 | 建议上限 | 当前 | 余量 |
|------|----------|------|------|
| `isr_delta`（TIM1） | **< 2500**（硬限 2700） | ~1200 | ~1300 / ~1500 |
| `motor_path_cpu`（TIM1 + SPI DMA ISR） | **< 3200～3500**（经验，留 RTOS） | **~1515** | **~1685～1985** |
| 每 100 拍 telem 写帧 | 预留 spike **~100～200** | — | 从 TIM1 余量扣 |

> **FOC 新增代码主要进 TIM1**，每 +1 cycle `isr_delta` 都直接逼近 **2700 红线**；SPI **~581/拍** 已固定，FOC **无法省掉**（除非降读角频率，当前不可接受）。

| 指标 | cycle/拍 | µs @ 160 MHz | 占 8000 | 说明 |
|------|----------|--------------|---------|------|
| `enc_dma_kick_delta`（SPI kick） | 254 | 1.6 | 3.2% | 含在 `isr_delta` 内 |
| `enc_dma_cpu_delta`（SPI F1+F2） | 315 | 2.0 | 3.9% | DMA ISR，**不含**在 `isr_delta` |

| **SVPWM + SPI（CPU）** | **~1450** | **~9.0** | **18.1%** | SVPWM + enc_spi_cpu_total |
| `isr_delta`（TIM1 全段） | 1200 | 7.5 | 15.0% | kick + SVPWM + 读角 + telem + DWT |

**Watch 快速核对（同一快照）：**

```text
enc_spi_cpu_total = enc_dma_kick_delta + enc_dma_f1_cb_delta + enc_dma_f2_cb_delta  ≈ 581
motor_path_cpu    = isr_delta + enc_dma_cpu_delta  ≈ 1515
（enc_dma_cpu_delta 应等于 f1_cb + f2_cb；enc_total_delta 字段同 motor_path_cpu）
```

### 3.5 SVPWM + SPI 耗时与「算不算长」

**@ 160 MHz，当前 -O2 稳定 Watch（P0 后）：**

| 项目 | cycle | µs | 备注 |
|------|-------|-----|------|
| SPI 全路径 CPU | ~581 | ~3.6 | kick + DMA f1/f2 |
| SVPWM（`setPhaseVoltage`） | ~870 | ~5.4 | CORDIC + float，从 TIM1 分解 |
| **SVPWM + SPI（CPU 合计）** | **~1450** | **~9.0** | 占 50 µs 一拍 **~18%** |
| `motor_path_cpu`（+读角/telem） | ~1515 | ~9.5 | **~19% CPU/拍** |
| `enc_dma_seq_delta`（墙钟） | ~1972 | ~12.3 | **非 CPU**；含硬件 SPI 等待 |

**结论（相对本工程）：**

| 对比 | 判断 |
|------|------|
| vs 50 µs / 8000 cycle 理论上限 | **不长**（~19%） |
| vs `isr_delta` 红线 **2700** | **远未触线**（1200 ≈ 44% 红线） |
| vs 历史 fat SVPWM **5800** | 已 diet **~4×** |
| 20 kHz 有感 FOC 常见占用 | 热路径 **20%～30%** 正常；**可上 FOC** |

真正要盯的是 **FOC 全进 TIM1 后 `isr_delta` 是否逼近 2400+**，不是当前开环基线。

## 四、遇到的问题与解决方案（详细）

### 4.1 链接错误：`motor_trig_sincos` undefined

**编译日志：**

```text
Error: L6218E: Undefined symbol motor_trig_sincos (referred from trans.o).
```

**原因：** `trans.c` 已 `#include "motor_trig.h"` 并调用 `motor_trig_sincos`；磁盘上有 `motor_trig*.c`，但 **Keil `uvprojx` 未加入**。

**解决：**

- `uvprojx` 追加：`motor_trig.c`、`motor_trig_cordic.c`、`motor_trig_lut.c`  
- `main.c`：`#include "motor_trig.h"`，`MX_CORDIC_Init()` 后 `motor_trig_init()`  
- 默认 backend：`motor_trig_cfg.h` → `MOTOR_TRIG_BACKEND_CORDIC`

---

### 4.2 编码器 DMA「死掉」（两阶段）

#### 阶段 A：LL + HAL 混用 Ch2

**Watch 典型（故障）：**

| 字段 | 值 |
|------|-----|
| `enc_dma_phase` | 1（FRAME1） |
| `enc_dma_busy` | 1 |
| `enc_kick_cnt` | 2 |
| `enc_cplt_cnt` | 1 |
| `enc_kick_skip_busy` | **70 万+** |
| `enc_raw` | 冻结 |

**机理：** 第一次完整读可能成功；**第二次 kick 后 FRAME1 的 DMA TC 不再被正确服务**，`phase` 永驻 FRAME1，之后每次 TIM1 `encoder_kick` 因 `phase != IDLE` 走 `enc_kick_skip_busy`。

**根因：** `DMA1_Channel2_IRQHandler` 先调 `board_encoder_m1_dma_isr()`（LL），再调 **`HAL_DMA_IRQHandler(&hdma_spi1_rx)`**。编码器路径 **不经 HAL_DMA_Start**，HAL 二次处理会破坏 Ch2 状态。  
架构文档 [`SPI编码器架构实现说明.md`](./SPI编码器架构实现说明.md) §5.3 明确要求：**Ch2 仅 LL，不要 HAL**。

**解决：** 删除 Ch2 上的 `HAL_DMA_IRQHandler`。

#### 阶段 B：Cube 关闭 NVIC 生成后无 ISR

**现象：** 阶段 A 修完后仍可能「全死」，`.map` 显示：

```text
DMA1_Channel2_IRQHandler → startup_stm32g474xx.o (Thumb Code 0)
board_encoder_m1_dma_isr → Removing (dead code)
```

**根因：** CubeMX **取消勾选 DMA1 Channel2 中断** 后，不再生成 IRQHandler；USER CODE 里 **未补** 手写入口 → 向量进 **weak 空桩**，DMA 永不进状态机。

**解决（长期）：**

1. Cube：**保留** SPI1 RX/TX DMA 配置；NVIC **取消** Ch2（建议 Ch3）自动生成。  
2. `stm32g4xx_it.c` **`USER CODE BEGIN 1`**（Generate 保留）：

```c
void DMA1_Channel2_IRQHandler(void)
{
  board_encoder_m1_dma_isr();
}
```

3. `dma.c` **保留** `HAL_NVIC_EnableIRQ(DMA1_Channel2_IRQn)`，prio **2**（低于 TIM1 的 **1**）。  
4. Generate 后查 `.map`：Ch2 入口必须在 `stm32g4xx_it.o`。

**修复后 Watch（健康）：**

| 字段 | 典型 |
|------|------|
| `enc_kick_cnt` ≈ `enc_cplt_cnt` | 同步增长（~42 万+） |
| `enc_kick_skip_busy` | **0** |
| `enc_dma_busy` | 0（快照瞬态可为 1） |
| `enc_raw` | 随转子变化 |

### 4.3 `setPhaseVoltage` 被注释 — 有角无 PWM

**现象：** 编码器计数正常，电机不转。

**原因：** 合并 `main.c` 时 SVPWM 仍在 `#if !BRINGUP_ADC_TEST` 或注释块内；`BRINGUP_ADC_TEST=1` 时只开 TIM1。

**解决：** TIM1 回调内，读角后 **无条件**：

```c
as5047_spi1.get = encoder_get_theta_el(&enc_m1, enc_raw, M1_POLE_PAIRS, as5047_spi1.add);
setPhaseVoltage(&htim1, uq, 0.0f, as5047_spi1.get);
```

---

### 4.6 P0：去掉冗余 `_normalizeAngle`（已完成）

**改前：** `encoder_get_theta_el(..., 0)` 后再 `_normalizeAngle(get + add)` — float 除法 + `%`，**~115 cycle**（1315→1200）。

**改后：** `add` 作为 `offset_rad` 传入 `encoder_get_theta_el`，L2 `as5047_raw_to_theta_mech` 用加减 `2π` 归一化；`setPhaseVoltage` 直接用 `as5047_spi1.get`。

```c
as5047_spi1.get = encoder_get_theta_el(&enc_m1, enc_raw, M1_POLE_PAIRS, as5047_spi1.add);
setPhaseVoltage(&htim1, uq, 0.0f, as5047_spi1.get);
```

**Watch 验证（-O2）：** `isr_delta` **1315 → 1200**；`motor_path_cpu` **1654 → 1515**；电机仍转，RTOS 正常。

### 4.4 极对数 14 vs 7 — 编码器活但电机不转

**现象：** DMA 健康，`isr_delta` 正常，**电机不转或只抖**。

**原因：**

```c
#define M1_POLE_PAIRS 14u   // 合并 encoder API 时误设
as5047_spi1.get = encoder_get_theta_el(..., M1_POLE_PAIRS, 0.0f);
```

误跟 `FOC_CAL.c` 的 `elect_pair_num = 14`；同文件注释写 **tmotor_u3 = 7 对极**。历史可转代码为 `GetAngle(...) * 7`。

**混淆点：** AS5047 **14 bit** 是编码器分辨率，**不是** 极对数。

**解决：** `#define M1_POLE_PAIRS 7u` → **电机恢复旋转**（用户原话：赞美欧姆弥赛亚）。

**角度链（当前，含 P0）：**

```c
as5047_spi1.get = encoder_get_theta_el(&enc_m1, enc_raw, M1_POLE_PAIRS, as5047_spi1.add);
setPhaseVoltage(&htim1, uq, 0.0f, as5047_spi1.get);  // add≈2.1 from angle_init()
```

---

### 4.5 kick 顺序与 DMA 被 TIM1 挡住

**讨论：** 是否 kick 放 SVPWM 后？DMA ISR 是否被 FOC ISR 打断？

**结论摘要：**

| 问题 | 答案 |
|------|------|
| 本拍 SVPWM 用的哪次采样？ | **上一拍** kick 完成的 `raw`（**固定 1 拍延迟**，~50 µs） |
| 调换 kick 与 SVPWM 顺序？ | **不改变** 本拍用角；不能靠此降 cycle |
| kick 为何在 SVPWM 前？ | 尽早启动 SPI，在 50 µs 内完成双帧；`enc_kick_skip_busy=0` |
| TIM1 prio 1 > DMA prio 2 | **刻意**：DMA 回调在 TIM1 退出后跑，避免 CCR 更新 jitter |
| 2 拍旧角换更短 cycle？ | **不能**自动减 cycle；须降 SVPWM 频率或 ISR 只写 CCR，不推荐 bringup 用 |

## 五、当前软件架构

### 5.1 TIM1 回调顺序（`main.c`）

```text
HAL_TIM_PeriodElapsedCallback (htim1)
│
├─ DWT isr_t0
├─ encoder_kick(&enc_m1)                    ~254 cycle（Watch: enc_dma_kick_delta）
├─ enc_raw = encoder_get_raw(&enc_m1)       读缓存，无 SPI
├─ encoder_get_theta_el(..., 7, add)        ~30–50 cycle；offset 一次归一化
├─ as5047_spi1.raw / .get  ← 兼容 VOFA ch3
├─ setPhaseVoltage(htim1, uq, 0, get)     Ud=0 快路径 + CORDIC
├─ telem_bringup_tick()                     99/100 拍轻；1/100 拍写帧
└─ DWT isr_t1 → isr_delta                   ~1200 总计
```

### 5.2 DMA 回调（prio 2，`stm32g4xx_it.c` USER CODE）

```text
DMA1_Channel2_IRQHandler
  → board_encoder_m1_dma_isr()
  → encoder_spi_bus_fast_spi1 (LL)
  → as5047_async F1/F2 状态机
  → enc_dma_cpu_delta ≈ 315 (274 + 53)
```

### 5.3 SVPWM / trig 模块要点

**`bringup/trans.c`（相对旧版已 diet）：**

- Ud=0：**无** `atan2` / `sqrt` / 4×`arm_sin`  
- `_normalizeAngle`：整数 `%`（`16384×7` 电角计数），非 `fmod`  
- `svpwm_t1_t2_from_theta`：**1×** `motor_trig_sincos` + sin 恒等式  
- `PWM_Period = 3999`（与 Cube TIM1 一致）  
- 直接写 `htim->Instance->CCR1/2/3`

**`bringup/motor_trig`：**

- 编译期选 CORDIC / LUT（`motor_trig_cfg.h`）  
- CORDIC：Cosine 模式，1 write 2 read，寄存器 poll `RRDY`  
- 当前默认 **CORDIC**  
- **扇区 1～6** 已由公式 + `switch(sector)` 分配 Ta/Tb/Tc（**不是 sin 查表**）  
- P1「sector Q15 LUT」指 **扇区内 `[0,π/3]` 的 sin(θ)/sin(π/3−θ)** 替 CORDIC，与 `motor_trig` 全角 LUT backend 不同  
- 全角 float LUT（`math_tables`）WCET 曾略慢于 CORDIC；**sector Q15 小表** 需单独 WCET（用户实测可更快）

### 5.4 角度延迟语义

```text
TIM1 第 N 拍:  kick(N) 启动读；get_raw() = θ(N−1)；SVPWM 用 θ(N−1)
TIM1 第 N+1 拍: get_raw() = θ(N)；SVPWM 用 θ(N)
```

FOC 阶段应用 **PLL 2 kHz + 20 kHz 内插**，而非简单改成 2 拍旧角。

### 5.5 遥测与 `isr_delta` 读数注意

- `isr_delta`、`ch2_wire` **长期显示同一值（如 1200）** 正常：路径稳定 + Watch 白底表示「相对上次刷新未变」。  
- `isr_t0` / `isr_t1` / `cyccnt_end` **持续涨** 说明 ISR 在跑。  
- `ch2_wire` / `time_cnt` 仅 **每 100 拍** 写帧时更新（200 Hz），且拷贝的是 **上一拍** 的 `isr_delta`（DWT 在 telem 之后更新）。

### 6.3 相对预算的结论（含 SPI）

| 指标 | 当前 | 硬限/目标 | 余量 |
|------|------|-----------|------|
| `isr_delta`（TIM1） | **~1200** | **≤ 2700**（建议 < 2500） | **~1500 / ~1300** |
| `motor_path_cpu`（TIM1 + SPI DMA） | **~1515** | **~3200～3500**（经验） | **~1685～1985** |
| 其中 SPI（`enc_spi_cpu_total`） | **~581** | 固定 | FOC **无法回收** |
| SVPWM + SPI（CPU） | **~1450** | — | 占 50 µs **~18%**，**不算长** |

- **当前 1200 << 2700**，RTOS + VOFA 与电机 **可同时工作**；motor 路径 **~1515/拍 (~19% CPU)**。  
- 后续 FOC 主要进 TIM1；规划以 **`motor_path_cpu ~1515` 为起点**。  
- FOC 在 TIM1 内可增加 **~1000～1300 cycle**（硬限 ~1500，建议留 telem spike **~100～200**）仍可能安全，但必须：  
  - **共用 1 次 sincos**（Park + SVPWM）  
  - 避免 reintroduce `fmod`/双精度  
  - 联调时监控 **`uart_task_loops` 是否仍涨**、`acquire_fail` 是否爆  
  - Watch 核对：`enc_spi_cpu_total ≈ 581`，`motor_path_cpu ≈ 1515`
