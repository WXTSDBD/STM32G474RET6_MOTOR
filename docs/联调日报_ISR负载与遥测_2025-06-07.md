# 联调日报：ISR 负载与遥测共存（2025-06-07）

> STM32G474RET6 电机 bringup · LPUART 6Mbps + JustFloat + VOFA+  
> 业务代码在 `bringup/`，尽量少改 CubeMX 生成文件。

---

## 一、今天做了什么（按时间线）

### 1. 明确 CPU 瓶颈在哪

- 用 DWT（`g_telem_dbg.isr_delta`）在 **TIM1 20kHz ISR** 里量周期消耗。
- 结论：**不是遥测太重，是 `setPhaseVoltage()` 里的库函数太重**；遥测摊销约 **~60 cycle/拍**。

### 2. 做 ISR 负载二分（不连电机）

对 `bringup/trans.c` 里 `setPhaseVoltage()` **逐项注释**，测 `isr_delta` 与 VOFA 是否恢复：

| 配置 | `isr_delta`（约） | VOFA |
|------|-------------------|------|
| 完整（atan2 + nor + sqrt） | **7200** | 不行 |
| 去掉 `atan2f` | **6625** | 不行 |
| 再去掉 `_normalizeAngle`（`fmod`） | **5801** | 不行 |
| 再去掉 `sqrt` / `Uref` | **2719** | **可以** |
| 再去掉遥测 | **2660** | — |

**遥测增量：2719 ? 2660 ≈ 59 cycle**（可忽略）。

### 3. 验证「nor 开/关」与遥测关系（关键结论）

- **nor 开**（`_normalizeAngle` 走双精度 `fmod`）：`isr_delta` ~5800 档 → **`uart_task_loops = 0`**，`acquire_fail` 暴涨 → VOFA 停。
- **nor 关**：`isr_delta` **~2707** → 任务跑 **5 万+** 次，DMA 发 **98** 包，`acquire_fail = 0` → VOFA 正常。

**因果链（已用 Watch 证实，非混合故障）：**

```
fmod(nor) → ISR +~800 cycle → 总负载 ~72% CPU
         → FreeRTOS 发送任务饿死
         → 双缓冲 READY 无人取 → acquire_fail ↑ → VOFA 停

关掉 nor → ISR ~34% → 任务能调度 → DMA 正常
```

### 4. 加可观测变量（`g_telem_dbg` 扩展）

在 `bringup/app_uart_dma_debug.c/.h` 增加调试字段，Keil Watch 展开 **`g_telem_dbg`** 即可：

| 类别 | 字段 | 用途 |
|------|------|------|
| ISR 写 | `tick_total`, `tick_frame_ok`, `acquire_fail`, `seal_cnt` | 写缓冲是否堵死 |
| 任务发 | `uart_task_loops`, `try_send_calls`, `dma_start_ok`, `tx_cplt_cnt` | 任务/DMA 是否跑 |
| 跳过原因 | `dma_busy_skip`, `no_ready_skip` | 为何没发起 DMA |
| 快照 | `buf0/1_state`, `uart_gstate`, `last_dma_bytes` | 缓冲与 UART 状态 |

缓冲 state：`0=UNLOCKED 1=LOCKED 2=READY 3=SENDING`  
`uart_gstate`：`0x20=READY`，`0x21=BUSY_TX`

### 5. 排除过的方向

| 方向 | 结论 |
|------|------|
| 遥测双缓冲 + DMA 架构 | **正确**，nor 关时链路健康 |
| 单纯提高 RTOS 任务优先级 | nor 开时仍饿死；**根因是 CPU 时间片，不是优先级 alone** |
| RTOS 栈/堆太大 | nor 关时同配置跑 5 万 loop；**不是堆问题** |
| Flash Download `Contents mismatch` | 烧录/调试连接问题，与算法无关 |

### 6. 其它零碎

- 恢复过误改的 `main.c` / `app_uart_dma_debug.c`（TIM1 PWM、SVPWM、`telem_bringup_tick` 等）。
- 了解 `git stash` 暂存未提交改动。
- 讨论不连电机时用 `isr_burn_cycles()` 扫 ISR 预算上限（思路，未必须落地）。

## 二、当前架构（工作配置）

```
TIM1 ISR (20kHz)
  ├─ AS5047 SPI1 读角度
  ├─ setPhaseVoltage()  ← 须轻量（nor/sqrt/atan2 不能开）
  ├─ telem_bringup_tick() 写双缓冲
  └─ DWT → g_telem_dbg.isr_delta

RTOS 任务 UART_DMA_DEBUG
  └─ telem_bringup_try_send() → HAL_UART_Transmit_DMA (6Mbps)

HAL_UART_TxCpltCallback → 缓冲 SENDING → UNLOCKED
```

| 文件 | 作用 |
|------|------|
| `Core/Src/main.c` | TIM1 ISR、电机调用、`BRINGUP_ADC_TEST` |
| `bringup/app_uart_dma_debug.c` | 双缓冲遥测 + DMA 任务 + 调试计数 |
| `bringup/trans.c` | `setPhaseVoltage()` — **优化主战场** |
| `bringup/as5047.c` | 编码器 SPI（~1500 cycle） |
| `Core/Src/app_freertos.c` | `UART_DMA_DEBUG` 任务（当前 `osPriorityHigh`） |

**VOFA+**：6000000，JustFloat，4 通道；ch1/ch2 为 uint32 原样小端，**勿当 float 看**，以 Watch `isr_delta` 为准。

## 三、实测数据备忘

### ISR 周期预算（@160MHz，20kHz → 8000 cycle/拍）

| 模块 | 约 cycle |
|------|----------|
| AS5047 SPI1 阻塞读 | ~1500 |
| `setPhaseVoltage` 重库函数（sqrt+atan2+nor） | ~4000+ |
| `_normalizeAngle` ×2（`fmod` 双精度） | ~800 |
| `atan2f` | ~575 |
| `sqrt` | ~3000 |
| 轻量 SVPWM（反 Park + sin/cos + 扇区） | ~1000~1200 |
| 遥测 `telem_bringup_tick` | ~60（均摊） |

### 常态 FOC 目标（今日结论）

| 等级 | `isr_delta` | 占 50?s 周期 |
|------|-------------|--------------|
| **推荐** | **≤ 3000~3200** | ≤ 40% |
| 可接受 | ≤ 3500~3800 | ≤ 47% |
| 危险 | ≥ 4500 | ≥ 56% |
| 不可用（已验证） | ≥ 5500 | ≥ 69% |

验收：Watch 里 **`isr_delta` 稳定 < 3200**，且 **`uart_task_loops`、`dma_start_ok`、`tx_cplt_cnt` 持续增长**。

### nor 关、工作正常时参考（Watch 快照）

```
isr_delta        ≈ 2707
uart_task_loops  ≈ 50312
dma_start_ok     ≈ 98
tx_cplt_cnt      ≈ 98
acquire_fail     = 0
seal_cnt         ≈ 98
uart_gstate      = 32 (0x20 READY)
last_dma_bytes   = 4080
```

`no_ready_skip` 很高是**正常现象**（任务 1ms 轮询，缓冲约 1s 封一包）。

## 四、根因一句话

**20kHz TIM1 ISR 里 `setPhaseVoltage` 使用 `fmod`/`sqrt`/`atan2` 等重库函数，CPU 占满后饿死 FreeRTOS 遥测发送任务；关掉 nor（及 sqrt/atan2）后 ISR 回到 ~2700 cycle，遥测与电机 bringup 可并存。**

不是 LPUART/DMA/双缓冲设计错误，也不是 RTOS「栈太重」，而是 **ISR 数学实现必须轻量化**。

## 五、`trans.c` 当前风险（联调电机前必改）

注释掉 `sqrt` / `atan2` 后若未补逻辑：

- **`Uref` 未初始化**即参与 T1/T2 计算；
- **`angle_ref` 固定为 0**，未使用入参 **`angle_el`**；
- 扇区恒为 1，**不能正确驱动电机**。

bringup 正确做法：

- 用 **`angle_el` 直接算扇区**：`sector = (int)(angle_el / _PI_3) % 6 + 1`
- **`Uref` 常数或预计算**（固定 `Uq` 时：`Uref = fabsf(Uq) / voltage_power_supply`）
- 角度归一化用 **float 加减**，**禁止 `fmod` 双精度**

## 六、明天 / 后续建议

1. **实现轻量 `setPhaseVoltage_bringup()`**（已知 `angle_el`，无 atan2/fmod/sqrt），目标 `isr_delta < 3000`。
2. 评估 **SPI 降频**（每 2/4 拍读角度），为完整电流环腾 ~750~1100 cycle。
3. 加电流环后复测 `isr_delta`，全 FOC 目标 **≤ 3500**。
4. 确认 `BRINGUP_ADC_TEST=1` 时 TIM1 三相 PWM 是否按预期输出（联调电机时）。
5. 保留 `g_telem_dbg` 调试字段至 FOC 稳定后再考虑裁剪。
