# 改完就自检（这是你的眼睛）

## 为什么有这条规矩

Cursor 改完文件，IDE 会**立刻**把编译错误回传给它
（协议里有 `read_lints`、`were_all_new_linter_errors_resolved_by_this_edit` 这些字段）。

**你拿不到。** 你改完是瞎的 —— 不自己查，就只能等 Keil 全量编译（1~2 分钟），
或者等主人发现。这是你和 Cursor 之间**最大的一个能力差**。

`tools/quickcheck.ps1` 就是补这只眼睛：约 **1.8 秒/文件**，
用 Keil 自带的 armclang 做单文件语法/类型检查，**判定与 Keil 一致**（已实测对齐）。

## 什么时候必须跑

**改了任何 `.c` / `.h`（含 `config/` 下的宏、`profiles/*.profile.h`）之后，
做下一个动作之前。**

不是"交付前跑一次"，是**每次改完就跑**。这就是 Cursor 的行为。

## 怎么跑

```powershell
# 1) 最常用：自动查 git 改动过的 .c
.\tools\quickcheck.ps1

# 2) 只看某几个文件
.\tools\quickcheck.ps1 motor\motor_current.c motor\observer\emf_pll.c

# 3) 更严（加 -Wall，会报出 Keil 不报的警告，仅作参考）
.\tools\quickcheck.ps1 -Strict
```

## 看退出码

| 退出码 | 含义 | 该做什么 |
|---|---|---|
| 0 | 干净 | 继续下一步 |
| 1 | 有 error 或 warning | **先修干净**，修完重跑 |
| 2 | 环境问题（找不到 armclang / .uvprojx） | 报告主人，别自己乱装工具 |

## 硬规矩

- 出现 `[ERR ]` → **不许继续**，不许说"这个错误应该不影响"。
- 修完**重跑**，直到全绿。
- 同一个错**修 3 轮还不过 → 停下来问主人**，别硬顶、别反复猜。
- 跑过了只说明"单文件语法/类型干净"，**不代表能烧录**。
  交付前仍须按 `10-交付前编译.md` 跑完整 Keil，结果必须 `0 Error(s) 0 Warning(s)`。
- 引用结论时标明来源，例如：`【事实】quickcheck 通过（0 error / 0 warning）`。

## 绝对不许做

- **不许**为了通过自检去注释掉报错的代码、加 `#if 0`、乱强转类型消警告。
  **那是造假**，主人一眼看得出来。
- **不许**自检没过就跑 Keil 全量编译"看看到底行不行"。**先修，再编。**
- **不许**跳过自检直接告诉主人"改好了"。

## 已知限制（写出来免得你误解）

- 只查语法和类型，**不查链接**（未定义符号、重复定义查不出来）。
- 只查你指定的文件，**不查被它影响的其它文件**。
- 头文件单独查只是"这一份头文件自己能不能解析"，不代表所有包含它的地方都对。
  → 所以改完头文件，**顺手把包含它的 `.c` 也传给 quickcheck**。
