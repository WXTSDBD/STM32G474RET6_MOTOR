**三条关键发现（含定量证据，这是本段最有价值的部分）**：

```text
F1 位置环是一阶 1 Hz：
   Kp_pos = 60 rpm/rad = 6.283 1/s → τ = 0.159 s → 3τ = 0.478 s
   实测进 6° 时间 0.44–0.55 s  ←→  完全吻合
```

## 12. 架构解耦评估：平台化 / 可移植（HAL → Driver → BSP → App 逐层内推）

**本节触发（v1.2）**：作者二次质疑——面向后续 **换编码器 / 换电机 / 换平台（G4 其他型号 → STM32 其他系列 → 国产 GD32）**，现有架构是否明晰、文档是否够用、是否存在对"平台化"的认识不足。

> **本节范围（重要）**：以下 **P1~P10 与 R1~R5 是面向未来变更（换编码器 / 换电机 / 换芯片）的债**，

### 12.1 四层对齐：作者的模型 ↔ 工程实际

### 12.2 可移植三轴实测（逐文件扫描，2026-10-07）

#### ① HAL 触碰普查

判据：文件内出现 `stm32g4xx` / `#include "tim.h"|"adc.h"|"spi.h"|"fdcan.h"` / `HAL_` / `__HAL_` / `LL_` 任一。

| 目录 | 文件数 | **碰 HAL** | 说明 |
|---|---|---|---|
| `motor/observer/` | 23 | **0** | 纯算法 |
| `motor/ident/` | 9 | **0** | 纯算法 |
| `motor/deadband/` | 15 | **0** | 纯算法 |
| `motor/speed_ident/` | 4 | **0** | 纯算法 |
| `motor/`（根） | 73 | **1** | 仅 `foc_svpwm.c`（`motor_current.h` 那条是**注释里提到回调名**，非 include） |
| `platform/` | 11 | 4 | ✅ 契约层，**故意**（`pwm_port_stm32g4_reg` / `adc_sample_stm32g4` / `encoder_spi_bus_fast_spi1` / `encoder_spi_bus_generic_g4`） |
| `config/` | 15 | 3 | ✅ 唯一 HAL 入口（`hal_bridge.h` / `bridge_cubemx.c` / `bsp_axes.c`） |
| `board/` | 4 | 2 | ✅ 板级 |
| `drivers/foc/` | 8 | 1 | ⚠️ `motor_trig_cordic.c`（G4 专有外设） |
| `debug/` | 4 | 2 | ⚠️ 遥测层（`app_uart_dma_debug.c` / `dbg_monitor.h`） |
| `bringup/` | 6 | 2 | ⚠️ `COMMUNICATION_FDCAN.*`（legacy 调速口） |
| `cal/` | 9 | **5** | ❌ **业务层却吃 HAL 句柄** |

> **关键读数**：**算法主体 51 个文件**（observer 23 + ident 9 + deadband 15 + speed_ident 4）**100% 零 HAL 符号**。这是被现有文档低估的**平台资产**。
> ⚠️ **但"零 HAL 符号" ≠ "换平台不用改"**（v1.2 收紧）：这 51 个文件仍通过 `obs_cfg.h` 吃进那份 3000+ 行总配置（§12.3 P2/P4）。换平台时若编不过，**要改的是这条依赖，不是这 51 个 `.c` 本身**。
> 准确说法是：**"算法体不用重写，但依赖链要断"**。
> `platform/` 里那 4 个碰 HAL 的文件，**正是"换平台要新写的全部后端"**——反向证明 Port 模式在起作用。

#### ② 三种变更 × 逐层推演

| 变更 | HAL | 总线 / 驱动 | BSP / 设备 | 算法 | 配置 / App | 判定 |
|---|---|---|---|---|---|---|
| **换编码器芯片** | 不动 | ✅ ops 表（`encoder_spi_bus_ops` / `encoder_driver_t`） | ⚠️ 改 `board_encoder_m1.c` 绑定 + 零偏重标 | ✅ 不动 | ✅ 不动 | **低**（但**从未被行使过**：至今只有 AS5047 一颗） |
| **换电机** | 不动 | 不动 | 不动 | ⚠️ 改的是**参数值**（R / Ld / Lq / ψf / 极对数 / 限幅） | ⚠️ 要打开**同一个 3370 行文件**（可读性问题） | **低（填数）**；痛在"铭牌与实验开关混编" |
| **换 MCU / GD32** | ❌ 重生成 + 写 4 个 backend | ❌ `cal/`(5) / `debug/`(2) / `bringup/`(2) 吃 HAL | ⚠️ `foc_svpwm.c` | ⚠️ 算法体不重写，但**要断 `obs_cfg` 依赖** | ⚠️ 中断优先级 / 时钟树 / **CORDIC 作废（只能走 LUT）** | **工程量最大** |

> **顺序判断（v1.2 修订）**：**换电机**改的是**参数值**（R / Ld / Lq / ψf / 极对数 / 限幅）——是**填数**，代价低；**换 MCU / GD32** 要重写后端、时钟树、DMA 映射，**还要丢掉 CORDIC**（只能退回 LUT）——**后者才是真正的工程量**。
> **不要把"要打开同一个 3370 行大文件"（可读性 / 可维护性）当成"工程量更大"**；两者是**不同性质的债**（§12.3 P1/P4），不要混谈。

#### ③ 契约层泄漏（换芯片 / 换平台会咬）—— `platform/encoder_spi_bus.h`

| 字段 / 签名 | 泄漏了什么 |
|---|---|
| `int (*start_word)(bus, const uint16_t *tx, uint16_t *rx)` | **硬编码 16-bit 帧**。AS5047 是 16 位；换 24 位 BiSS/SSI 就要改**契约头** |
| `uint32_t dma_ll_rx_ch` / `dma_ll_tx_ch` | **STM32 的 DMA 请求号概念**进了 Port 契约；GD32 映射语义不同 |
| `void *cs_port` + `uint16_t cs_pin` | STM32 GPIO 概念 |

> 注：这三条**不影响当前使用**（只有 AS5047 + SPI1），但它们是**"契约看起来中立、实则绑芯片"**的典型样本，换平台前应先中立化。

### 12.4 对作者四层模型的三个裁定

作者原话（大意）：*"不同编码器 HAL 不一样，driver 的 SPI 可以适配，BSP 上对编码器数据的 PLL 处理可以用一样的，App 上可以考虑是否使用编码器"*，以及 *"不同算法（磁链观测、SMO）可以放在 driver 看；HAL 更多是根据不同电机做参数适配"*。

| # | 作者的说法 | 裁定 | 依据 |
|---|---|---|---|
| 1 | "不同编码器 **HAL** 不一样；**Driver** 的 SPI 可以适配" | ✅ **成立，且已实现**。但工程实际切分**不是三套 HAL**，而是三层正交：**芯片协议**（`Drivers/as5047`）／**总线 backend**（`encoder_spi_bus_ops`）／**设备 ops**（`encoder_driver_t`）。建议在文档里把这三分点名，避免继续混在 "Driver" 一个词里。 | `platform/encoder_spi_bus.h:60–61` 两张 ops 表共存；`encoder.h:43–58` ops 表 |
| 2 | "**BSP** 上对编码器数据的 **PLL** 处理可以用一样的" | ⚠️ **前提对、归属建议改**。PLL 确实与传感器无关、可复用；但**留在算法层比放 BSP 更对**：`motor_current.c:902–911` 显示"编码器 PLL 积分"与"SMO 转速"**汇合到同一个 `s_speed_fb_rpm`**（`observer_pub_ss() ≥ 1` 时切 SMO）。若放进板级 BSP，**无感路径就没有 PLL 可用**。→ 真正该进 BSP 的是**零偏 / 极对数 / unwrap 多圈 / 尺度**（即 P7 那三处散落的量）。 | `motor/motor_current.c:902–911` |
| 3 | "**App** 上可以考虑是否使用编码器" | ⚠️ **功能已做，但不是 App 层的决策**。现在是**编译期宏** `M1_ENC_OPTIONAL_ENABLE` / `M1_OUTER_THETA_FB_SRC`，判定点散在 `motor_current.c` 的 5 处 `#if`（`:678` / `:916` / `:1107` / `:1475` / `:1764`）。与 v3.0 §16「运行时 ops 表」的目标有差距。 | 同左 |

**关于"算法能不能放 driver"——本节明确不同意**：

- **driver 的判据是"是否耦合具体外设/硬件"**，不是"是否与某台电机相关"；
- **实测**：`motor/observer/` **23 个文件 0 HAL**（`emf_smo.c` / `emf_pll.c` 只 include `math.h` + `obs_cfg.h`）——它是**纯数学模型**，下沉到 driver 会**反向破坏分层**；
- 作者直觉里**真正对的那半句**是"**HAL 更多是根据不同电机做参数适配**"——**对，但落地方式是"给算法一个参数入口"，不是"把算法搬进 driver"**。缺的是 **P1 的运行时参数入口**。

> **一句话**：算法**按电机参数适配** ✅；算法**住在 driver 层** ❌。**缺的是"运行时参数入口"，不是"算法放错地方"。**

### 12.5 架构评级（v1.2 新增，与 §12.0 三把尺子对应）

| 轴 | 评级 | 一句话 |
|---|---|---|
| 设备侧解耦（PWM / ADC / SPI / 时间） | **A−** | Port 契约 + ops 表，**且有两个 SPI backend 的实证** |
| 算法侧解耦 | **C** | 只有 observer 一处真 ops；参数靠宏、调试靠全局 |
| **参数 / 配置解耦** | **C−** | 配置**有落点**（`config/profiles/*.profile.h`）；缺**运行时 `cfg` 结构**，且**电机铭牌与实验开关混编** |
| 命名与分层可读性 | **C+** | `Drivers/` 混 HAL 与自研；`platform/` 混契约与 backend；`cal/` 越层 |

> **总评（v1.2 修订）**：**架构的"接口"是明晰的；配置有落点，但只在编译期，缺的是运行时参数结构。**
> 四层模型要落地，缺的不是重构，而是三件事：**补运行时 `cfg`** + **把 `obs_cfg.h` 的伪解耦变成真反转** + **把电机铭牌与实验开关拆开**。

### 12.7 契约验证路线（比写文档更重要）

> **核心判断**：`encoder_driver_t` 声称"换芯片只换 driver 表"，但**至今只跑过 AS5047 一颗芯片**——**这是一个从未被行使过的抽象**。同理，"可移植性 8/10"也是未经第二平台验证的自评。
> 按本工程自己的纪律（**打通 ≠ 签收**），这两条都应记为 **待验证**。

| 候选 | 代价 | 能验证什么 |
|---|---|---|
| **A. 换一款不同接口的编码器**（SSI / ABZ / 另一颗磁编） | 低（半天 + 一次台架） | `encoder_driver_t` + `encoder_spi_bus_ops` 是否真的够用；**唯一能低成本证伪契约的机会** |

**不建议**在没有第二平台前写"GD32 移植代码"——v2.0 的 C++17 五层架构已经证明过这种"纸上架构"的代价（设计完整、落地 0）。

## 14. 实验 / 整定框架（v1.6 新增）

### 14.0 触发与关键发现

**触发**：作者提出——"实验以后只会多不会少（速度阶跃 / 电流扫频 / HFI-SMO 正反切，以后还有 ESO 带载与不带载、前馈 on/off），不想再用宏把它们串起来，本来应该是用 ops 表管理"。

**关键发现**：**这一题 v2.0 §10 已经答对了。**

`docs/电机驱动软件框架——完整架构设计文档.md §10 测试模式` 原文：

```
ITestCase 接口:  init() / tick(dt) / abort() / result()
测试用例:        FrequencySweep / StepResponse / ReversalTest
上位机通过 SDO:  选测试用例 → 设参数 → 启动 → 读状态 → 读结果
                **扫频在 MCU 内部执行，不需要逐点发指令**
```

> 最后那句正是当前"CANopen 未迁入 + 外部指令带宽不够"的答案：**激励永远在片内生成，外部只做控制面。**
> 所以本节不是新设计，是**把 §10 落地**——并补一件当时没想到的事：**表驱动**。

### 14.1 关键判断：你的实验 **80% 是"时间表"**

| 实验 | 形态 |
|---|---|
| 速度环阶跃（多档 × 多轮） | **时间表** |
| HFI-SMO 正反切（±1500 ×5） | **时间表** |
| 位置/MIT 签收（9 段） | **时间表**（现在就是 `OUTER_SIGN_SEG_*` 常量表） |
| MIT 推-放（先推 2 s 再松手） | **时间表** |
| 死区 LUT 阶梯 | **时间表 + 判据** |
| 前馈 on/off、ESO 带载/不带载 | **时间表 × 2 套配置** |
| 电流环扫频（57 点对数） | **脚本**（频率连续、相位连续） |
| Ld/Lq VASI（等半周完成才推进） | **脚本**（判据驱动推进） |
| HFI 起动（IPD→kick→crawl→run） | **脚本** |

**结论**：**不要给每个实验写一个 `tick()`**——那只是把 13 个 `M1_BRINGUP_MODE` 换成 13 个函数，问题原样搬家。
正确做法：**一张通用段表 + 一个通用执行器**覆盖 80%，剩下的 20% 用脚本接口挂同一个壳。
→ **加一个实验 = 加一张 `const` 表（几行数据），不是加一段代码。**

### 14.2 成功判据（可量化）

| | 加一个新实验要碰的文件 | 碰热路径？ |
|---|---|---|
| **现状** | ① `motor_params_m1.h`（模式枚举 + 门控）② 同文件（PI / 参数分支）③ `*_flow.c` 或 `motor_outer_loop.c`（时间表）④ `motor_current.c`（装配）⑤ `app_uart_dma_debug.c`（12ch 布局）⑥ profile ⑦ `bringup_active.h` = **6~8 处** | ❌ **碰** |
| **目标** | ① **新 `.c`（段表 + 可选脚本）** ② **注册表加 1 行** ③ **PC 判据脚本 1 个** = **3 处** | ✅ **全不碰** |

> **验收指标：加实验改 3 处，且不碰 `motor_current.c` / `app_uart_dma_debug.c` / `motor_params_m1.h`。**
> 达不到，说明框架设计错了，不是实验太特殊。

### 14.3 形状（三层 + 两张表）

**L1 · 动作库**（可复用的"段动作"）
```c
typedef struct {
    void (*enter)(motor_context_t *ctx, const exp_seg_t *seg);
    void (*update)(motor_context_t *ctx, const exp_seg_t *seg, float t_s);
} exp_action_ops_t;
/* 默认动作（覆盖 ~80%）：
 *   act_hold / act_theta_ref / act_omega_ref / act_iq_ff / act_cfg_set / act_stim */
```

**L2 · 段表 + 实验定义**（**作者要的那张表**）
```c
typedef struct {
    uint16_t dur_ms;
    uint8_t  act;                  /* 默认动作 id；=0xFF 时用 ops */
    const exp_action_ops_t *ops;   /* 可空 */
    float    p0, p1, p2;           /* 幅值 / 目标角 / 前馈电流… */
    uint8_t  cfg_idx;              /* 0=A, 1=B（对照实验） */
    uint8_t  mark;                 /* 打点号 → 遥测 ch11 */
    uint8_t  guard_mask;           /* 本段放开哪些守卫 */
} exp_seg_t;

typedef struct {
    uint8_t          id;
    const char      *name;
    uint8_t          kind;         /* SCHEDULE | SCRIPT | CALIB */
    const exp_seg_t *seg;  uint16_t seg_n;
    const exp_cfg_t *cfg;  uint8_t  cfg_n;      /* A/B… */
    uint8_t          telem_layout;
    const exp_script_ops_t *script;              /* kind==SCRIPT */
} exp_def_t;

extern const exp_def_t *const g_experiments[];   /* 静态注册表：加实验就加一行 */
```

**L3 · 配置结构**（**这就是 §12.3 P1 缺的"运行时参数结构"——同一件事**）
```c
typedef struct {
    uint8_t ff_en;        /* 前馈 on/off   ← ESO/前馈对照靠这一位 */
    uint8_t eso_en;       /* ESO on/off */
    uint8_t deadband_en;  /* 死区 on/off */
    uint8_t theta_src;    /* 给角源（编码器 / PLL / HFI θ̂） */
    float   pi_kp, pi_ki; /* 实验专用 PI（是"配置"，不再是"模式"） */
} exp_cfg_t;
```

**L4 · 脚本接口**（20% 特殊实验，与 v2.0 §10 的 `ITestCase` 同构）
```c
typedef struct {
    void (*init)(motor_context_t *ctx, const exp_cfg_t *cfg);
    void (*tick)(motor_context_t *ctx);       /* 只在 2 kHz 外环 */
    uint8_t (*done)(const motor_context_t *ctx);
} exp_script_ops_t;
```

**L5 · 遥测布局也做成表**（消掉 15+ 个 `M1_VOFA_*`）
```c
typedef struct { const char *nm; float (*get)(const void *); } telem_ch_t;
extern const telem_ch_t g_layout_signoff[12];   /* 实验定义里写 telem_layout 即可 */
```

### 14.4 执行器放哪、怎么不膨胀

- **位置**：新目录 `motor/experiment/`，`exp_runner.c` 只在 **2 kHz 外环**调一次
- **不进 20 kHz JEOC 链**（实验只改 `ctx` 的引用值与 cfg，不改时序）
- **防膨胀的唯一办法**：段里放**动作 ops**，**禁止 `switch (seg->type)`**
  → 否则三年后会长出**第二个 GATE 链**。加动作 = 加 `act_xxx.c` + 表里引用，**`exp_runner.c` 一行不改**。

### 14.5 对照实验的正确形态（ESO 带载/不带载、前馈 on/off）

**不要**"跑一遍 A → 改宏 → 再跑一遍 B"：温升、机械零点、编码器零偏、摩擦都会变，两遍不可比。

**要**：表里**连续两段只差 `cfg_idx`**，同一次上电跑完：
```c
{ .dur_ms = 3000, .act = ACT_OMEGA_REF, .p0 = 300.0f, .cfg_idx = 0, .mark = 10 },  /* 无 ESO */
{ .dur_ms = 1000, .act = ACT_HOLD,                                   .mark = 11 },
{ .dur_ms = 3000, .act = ACT_OMEGA_REF, .p0 = 300.0f, .cfg_idx = 1, .mark = 12 },  /* 有 ESO */
```
→ "**是否加前馈 / ESO**"变成**表里的一列**，不再是"两次固件"。
→ 载荷同理：**载荷也应是 cfg 的一项**（或同一张表跑两轮，标 `load_a/load_b`）。

### 14.6 判据与留档（PC 侧对齐）

**固件只做三件事**：发激励、打点、留原始数据。**判据全在 PC**。
理由：① 判据要看波形（Mp / settle / RMS / 相位），固件里做等于再写一套 DSP；② 判据会随认识变化（P-C 的 `iq_pk` 毛刺 → 改中值），改 PC 脚本不用重烧；③ 已有 95 个 `tools/*.py` + `_analyze_*` 资产。

**打点约定标准化**（替代现在各实验各自编码的 `open_seq`）：

| 段 | 含义 |
|---|---|
| 高 4 位 | `exp_id` |
| 中 6 位 | `seg_idx` |
| 低 2 位 | `cfg_idx` |

**落盘约定**（沿用现有）：
```
VOFA+CSV/<日期>/vofa+<YYYYMMDDHHMM>.csv
VOFA+CSV/<日期>/_analyze_<exp_name>.py     ← 判据脚本，与 CSV 同日期目录
MDK-ARM/_pkg/<日期>_<exp_name>/            ← hex + log + size + sha256 + profile 快照 + git.txt
docs/验收报告_<exp_name>_<日期>.md
```
**新增规范一条**：每个实验**必须**在 PC 侧有一个 `_analyze_<exp_name>.py`，**否则不许进注册表**。
（这条是"实验多而不乱"的唯一保证。）

### 14.7 四类实验，只有三类进表

| 类 | 例 | 判据在哪 | 结果去向 | 进注册表？ |
|---|---|---|---|---|
| **整定 CALIBRATION** | Rs / Ld-Lq、死区 LUT、编码器零偏 | 固件有效性门 + PC 复核 | **写 `factory_nvm`** | ✅ |
| **验收 ACCEPTANCE** | 速度阶跃、电流扫频、HFI-SMO 正反切 | **PC 脚本** | CSV + `docs/` 签收 | ✅ |
| **对照 A/B** | ESO 带载/不带载、前馈 on/off | PC 脚本（差值） | CSV + 对比报告 | ✅ |
| **探索 BRINGUP** | 各 `M1_*` 试探 | 人眼 | 废录波多 | ❌ **保持宏**（一次性） |

> **注册表只装"会被重复跑 + 要留档 + 要当验收"的实验；一次性探索不进表。**
> 否则新框架会变成**第二个宏串联**——只是从"宏"换成了"表"。

### 14.8 四条防退化纪律

1. **注册表只装上述三类**；探索继续用宏（写表比写一行 `#if` 慢，别硬套）。
2. **加动作 = 加文件，不改 `exp_runner.c`**（用函数指针，禁止 `switch (seg->type)`）。
3. **实验只改 cfg 与引用值，不许改热路径结构**；执行器只在 **2 kHz 外环**。
4. **没有 PC 判据脚本的实验，不许进注册表。**

### 14.9 分阶段计划（E0~E6，每步可单独停）

| 步 | 做什么 | 验收 | 档位 | 烧录 |
|---|---|---|---|---|
| **E0** | 建 `motor/experiment/`：`exp_def.h` + `exp_runner.c` + 注册表；**只把现有 9 段签收表原样搬成 `const exp_seg_t[]`**，行为逐拍等价 | **P3 金样 `2336` 可复现**（P-A…P-E / M-A…M-D 同结果） | 档 2（Size 会变） | **是** |
| **E1** | 把 `speed_ident_flow` 包成第二个（多档 × 多轮 = 纯表） | `120009`–`120012` 可复现 | 档 2 | 是 |
| **E2** | 抽激励基元 `stim_step` / `stim_sweep` / `stim_reversal` + `exp_script_ops_t`；把 Bode 扫频、正反切接进来 | 扫频 57 点、±1500×5 可复现 | 档 2 | 是 |
| **E3** | 加 `exp_cfg_t` 的 A/B：`ctx` 里加 `ff_en / eso_en / deadband_en / theta_src` **运行时副本**；`act_cfg_set` 生效 | **同一次上电跑 A/B**，差值可判 | **改行为** | 是 |

## 15. GATE 防复发：怎么防止"141 个关卡"再来一次（v1.6 新增）

### 15.0 现状：**半收口——树砍了，机制还在**

| 项 | 现状（2026-10-07 实测） |
|---|---|
| `#if GATE == N` 分支 | **只剩 1 处真代码**：`config/profiles/m1_hfi_standstill.profile.h:172`~`:314` 一个 `#if M1_HFI_GATE == 141` 大块；其余命中全在 `_pkg/20261006_E1/E2/` 历史包与 docs |
| `M1_HFI_GATE` 旋钮 | **还在**：`bringup_active.h:37-38`、`motor_params_m1.h:161-163`（默认 0）、`:1847-1849`（`#error` 守卫）、两个 profile 各一处 |
| 官方口径 | `backlog_只留141:37`："**`M1_HFI_GATE` 旋钮 留**：非 141 无路，靠 profile `#if GATE != 141`" |
| 收口方式 | **一次性专项**：`tools/_c_collapse_profile_141.py`（脚本）+ B2~B6 一轮，砍掉 **742 行** |

> **树砍了，但"起个新号"的心智模型没动。** 旋钮在 → 下一个实验来了，最自然的动作还是"再起一个号"。

### 15.1 141 个号是怎么长出来的（四步循环，每步当时都合理）

| 步 | 动作 | 当时为什么合理 |
|---|---|---|
| 1 | 想改一个数 → **直接改宏** | 最快 |
| 2 | 改完发现"昨天的录波不可比了" | 需要能回到**已知好状态** |
| 3 | → **复制一份基线，起个新号**（GATE N+1） | 冻结快照，最省事 |
| 4 | 代码里 `#if GATE == N` 选分支，**旧号不敢删**（"以后要回访"） | 怕丢能力 |

→ `#if` 树线性增长：**141 个号 → `hfi_sqwave.c` 峰值 253 条条件编译**。

**公平地说**：这是单人 + 亚稳态调试（无感锁相）下的**理性选择**。GATE 号其实**是一种版本控制**——只是做在了预处理器里。

### 15.2 根因：GATE 号是一个"**万能类型**"

| 差异类型 | 正确载体 | GATE 号的做法 | 代价 |
|---|---|---|---|
| **参数**不同（Kp / 门槛 / 阈值） | **运行时 cfg**（§14 L3） | 新号 + `#if` | 改一个数 = 一个固件版本 |
| **策略**不同（鉴相反相 A vs B） | **ops 表**（§14 L1/L4） | 新号 + `#if` | 策略不可运行时替换 |
| **版本**不同（结构性改动） | **git tag + `_pkg` 快照** | 新号 + `#if` | 历史沉在代码里 |

> **一个整数同时表达这三类差异 → 它必然吸走一切 → 141 个。**
> 而这三样的正确载体（cfg / ops / tag），**正是 §12 缺的"运行时 cfg"、§14 要做的"实验框架"、§15.3 要补的"归档"**——**同一把锁的三个面**。

### 15.3 防复发：四条机制（每条配判据与工具）

#### 机制 1 · 把"冻结"从代码搬到归档 —— **回访不走代码分支**

**判据**：能不能在**不改一行代码**的情况下复现"第 N 次实验"？

- **现状够强**：`_pkg/<日期>_<名>/` 已有 `hex + rebuild_log + size + sha256 + bringup/profile 快照`
- **但缺一样**：`【事实】_pkg/20261006_S1b_hold_after_done/` 只有那 6 个文件——**没有 git 记录**。加上工作区长期 dirty，**光靠包无法重建当时的源码**
- **补 `git.txt`**：
  ```
  commit : 6059b85
  branch : feat/obs-veq-bypass
  dirty  : yes   (9 文件 +1481/-11)
           config/bringup_active.h, motor/motor_outer_loop.c, ...
  ```
- 效果：回访 = `git checkout <hash>` + 拷回快照 → **代码里就不需要留 `#if`**

#### 机制 2 · 三分类归位（**根上的**）

> **硬规则：`#if` 只允许表达"能力开关"（`M1_XXX_ENABLE`，两态都长期维护）；
> 禁止表达"历史快照"。**

| 想留住的东西 | 放哪 |
|---|---|
| 一组旧参数值 | **实验 cfg 默认值 / 段表**（不是 `#if`） |
| A 方案 vs B 方案 | **ops 表两行**（不是两个 GATE 号） |
| 整个旧行为 | **git tag + `_pkg` 快照**，代码里**删掉** |

#### 机制 3 · 每刀即删（把"治理"从专项变成纪律）

- 现状：清理是**专项轮**（一次性脚本 + B2~B6），周期 **9-14 → 10-07 之间一次没开** → 积压 742 行
- 新纪律：**每刀收尾必问"这刀留下只有一次的 `#if` 了吗？"** → 有就当场删
- 落成**可自动检查**：`tools/check_gate_hygiene.ps1`（见 §15.4）接入**交付前检查**
  → 你们已用 `quickcheck.ps1` 养成"改完就查"的习惯，**这条路走得通**；否则纯纪律一定退化

#### 机制 4 · 收口要**删旋钮**，不只是删分支

- 现在 `M1_HFI_GATE` 旋钮还在 + `#error` 守卫还在 + `#if == 141` 还在 → **旋钮在 = 心智模型在**
- 建议**彻底删**：那段 `#if` 无条件化、`bringup_active.h` 的 `M1_HFI_GATE` 删掉、`#error` 守卫删掉
- ⚠️ **前提**：§14 的 **E3** 先提供"对照"的正规入口
  → **否则删了就没有 A/B 入口** ⇒ **"删 GATE"与"做实验框架"必须一起做**

### 15.4 工具：`tools/check_gate_hygiene.ps1` 要查什么

| # | 检查 | 现状基线 |
|---|---|---|
| 1 | `#if`/`#elif` 里出现 `== <数字>` / `!= <数字>`（≥3 位数优先）→ 疑似历史快照 | 代码里 **1 处**（`m1_hfi_standstill.profile.h:172`） |
| 2 | 编号/临时型宏名：`*_GATE`、`*_V[0-9]+$`、`*_bp`、`*_bak`、`*_OLD`、`*_NEW` | 有若干（`M1_OPEN_UQ_SWEEP_V0/1/2`、`M1_OPEN_PRE_ID_LADDER_V4`、历史 `.pre_*bak`） |

**输出**：文件 + 行号 + 命中模式；**退出码非 0 阻断交付**。

### 15.5 不要"消灭谱系"，而是**把谱系搬到标签**

保留"第 N 次尝试"的价值，但放在正确的地方：

```

```

代码里**只留当前交付档（无条件活体）**。
→ **回访 131 = `git checkout gate/131` + 拷快照，5 分钟**，不需要代码里有 131。
