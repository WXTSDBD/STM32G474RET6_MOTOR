# 规划：无感代码收口与接口冻结（2026-10-05）

**对象**：`motor/observer/`、`motor/motor_current.c` 中的无感/HFI 段、`config/profiles/m1_hfi_standstill.profile.h`  
**本文角色**：把 2026-10-05 的结构审查收成「这一轮代码改善必须做到什么、冻什么、不做什么」。  
**对照金样**：有感三环（电流/速度/位置编排）+ AS5047 五层（`Drivers/encoder` → chip → `encoder_spi_bus` → `board_encoder_m1`）。  
**架构口径**：[电机驱动软件框架——完整架构设计文档_v3.0.md](./电机驱动软件框架——完整架构设计文档_v3.0.md)（全 C、`observer_ops_t`）；编码器冻结见 [SPI编码器架构实现说明.md](./SPI编码器架构实现说明.md)；阶段验证原则见 [实装文件架构_2026-06-29.md](./实装文件架构_2026-06-29.md) §七。  
**不替代**：HFI 四步验收、SMO 结档、算法对错与 cycle 优化。那些仍以各自报告为准。

## 0. 一句话

> **无感路径已经能联调、能录波，但代码是 bringup 状态机堆在电流环上，不是观测器驱动。**  
> 这一轮先把结构收到「编码器那种薄 API + 单独的角度选择/交接层」，冻接口后再改算法或加 GATE。  
> 有感三环与 AS5047 骨架 **不在本轮解冻范围**。

## 1. 本轮要改善到什么程度（验收口径）

对齐编码器模块已经做到的事，而不是对齐 v2 C++ 愿景稿。  
F6（算法脱离 `motor_params_m1.h`）依据是 v3.0 **§十五**「把板差/电机差从算法源文件中剥出」，不是本轮新发明的要求。

| # | 做到 | 冻住的标志 | 不做到（本轮不做） |
|---|------|------------|-------------------|
| **F0** | 编码可维护 | 无感相关源文件能按 UTF-8 读中文；U+FFFD 处人工补完或删掉烂注释 | 全仓库 21 个文件一次清完 |
| **F1** | 关模块能链过 | `M1_HFI_ENABLE=0` 时头文件每个符号都有空桩；遥测不得只靠 GATE、不看 ENABLE | 删全部 GATE |
| **F2** | 热路径与遥测有明确共享规则 | ISR 写、任务读：双缓冲 / atomic / 或至少 `volatile` 快照；禁止任务直接抠文件级 `static` | 重写整个遥测 BSP |
| **F3** | 电流环不再实现 HFI | `motor_current.c` 里不再有 `static hfi_*` 滤波器/握手/发布；tick 只调用观测器与选择器 | 把 7000 行 HFI 一次拆成十个文件 |
| **F4** | 交接有模块，不长在 ISR 编排里 | 见 §4 第三题：推荐 **Composite 观测器**（MotorCore 仍只挂一个 `observer`）。**不要**把 HFI 握手塞进现有 `obs_soft_switch` 当第二个临时交接层 | 运行期随便切 GATE 编号 |
| **F5** | 统一薄 API | 落地 C 的观测器 ops。**完整 F5 在施工 P8**（tick 不再点名 `hfi_sqwave_*`）。P6 只冻角 3 入口、P7 只冻电压 3 入口，给定相留到 P8。HFI 必须两相位，禁止单次 `update` 连打两拍；inj 电压相在 observer 外。 | 本轮签收无感产品闭环 |
| **F6** | 配置与算法分开 | 算法 `.c` 不 `#include` 整份 `motor_params_m1.h`；数值从 cfg 结构或少量契约头进来。GATE 结论迁出源码注释 | 不重编就能切 141 号实验（可列为下一轮） |
| **F7** | 结构改动可归因 | 每阶段 **Keil 0 Error**（v3.0 §二十二.5）+ **VOFA 对比金样 CSV**（[实装文件架构](./实装文件架构_2026-06-29.md) §七）。F3/F5 是行为等价性改动：通道语义未改的 ch 必须与拆前金样逐通道一致，波形变了要立刻归因。金样在动手前钉死（现行 GATE 的一条录波），**不是**「代码看着干净了」 | 用 2026-06 电流辨识那条 CSV 当 HFI 金样 |

**联调许可位（写清，避免读 v3.0 §十五/§十七 误判违规）**  
v3.0 §十五把「驱动/策略选择」写成编译期宏（`#define OBSERVER_TYPE …`），§4.2 写「启动时选定一版」。本轮 **产品态** 仍遵守：profile 启动时选定 Composite 里有哪些源、ops 指针 init 后冻结（不违反「运行期不改 ops 指针」）。  
**联调态允许** Composite **内部**按门限在已挂好的多源之间交接 θ/ω（状态机，不是换函数指针）。这是对总则的显式许可，不是 silently 开洞。

**冻结之后允许**：算法 bugfix、注释、Watch 字段、**新文件**实现第二套 ops（对标 `board_encoder_m2`）。  
**冻结之后禁止**：再给 `hfi_sqwave.h` 加 `get_/set_`；再在 `motor_current.c` 里写 HFI 状态机；再改已冻 ops 签名（除非升版本另开结构）。

## 2. 对照金样（合格代码长什么样）

### 2.1 AS5047 / 编码器（已冻结，本轮当尺子）

```text
motor_current_tick
  → encoder_kick / encoder_get_raw / encoder_get_theta_el / encoder_get_angle
      → encoder_driver_t ops
          → as5047_async（协议与 DMA 状态机）
              → encoder_spi_bus ops
                  → board 绑定 SPI/DMA/CS
```

FOC **不**知道 DMA 通道、parity、双帧。Chip 层 **不** include 遥测。这就是薄 API。

### 2.2 设计里的观测器（文档有、C 没有）

v3.0 的 `observer_ops_t`：`init / update(ia,ib,ua,ub) / get_theta / get_omega / is_converged / reset`（与 v3.0 §4.2 逐字一致）。MotorCore 热路径只有 **一个** `observer` + `observer_self` 槽位（§4.4）。  
[项目进度对照_Foundation_2026-07-06.md](./项目进度对照_Foundation_2026-07-06.md) §6.2 已登记：

> IObserver | 编码器/SMO/HFI/ESO | 编码器 + `motor_pll.c` | 🔧 有感 ✅

即：**有感槽位已填，统一接口未落地。** 不是新债。

### 2.3 现状（无感）

```text
motor_current_tick
  → 先读编码器 L1（永远读）
  → #if 覆盖本地变量 theta_park：
        obs_soft_switch_apply
        hfi_sqwave_park_theta
        hfi_pub / emf_pll_theta_smooth / I/F 保持 …
  → 同文件内 static hfi_* ：陷波、超前、纹波、影子速度 PI、702 行握手
  → 再调 hfi_sqwave_on_angle / on_current、emf_veq/smo/pll_update
```

真实 HFI 次序（`motor_current.c`）被 **Park 隔开**，不能收成一次 `update`：

```text
3465  hfi_sqwave_on_angle(theta_enc_park, dt)     ← 相位 1
3466  theta_park = hfi_sqwave_park_theta(...)     ← 相位 1 产物立刻当本拍 Park 角
      …
3661  motor_trig_sincos(theta_park, …)
3662  Park_Transform_sc(iα, iβ, …, &id, &iq)
3668  hfi_sqwave_on_current(id, iq, iα, iβ)       ← 相位 2，吃本拍 Park 输出
```

`hfi_sqwave_on_current` 进 `hfi_demod_step(id, iq, …)`（约 5891 行起），不是吃采样原始值。

没有 `observer_ops_t`。HFI 是 GATE 状态机，而且 **不是纯角度源**（两相位 + inj/override）。SMO/VEQ/PLL 是旁路对照对象。

## 3. 目前的问题

### 3.1 结构（必须本轮处理）

| ID | 问题 | 证据（量级） |
|----|------|----------------|
| A | 模块边界崩溃 | `motor_current.c` **40** 个 `static hfi_*`；全文件 **51** 种 `hfi_sqwave_*`，其中 **`motor_current_tick` 内 42 种**；头文件 **64** 个 API，其中 **47** 个是访问器 |
| A′ | 观测器互耦 | `emf_pll.c` include 并调用 HFI/SMO：`:83` `emf_smo_get_lpf_hz()`；`:161`/`:187` `hfi_sqwave_get_pll_int_el()`（相位前馈绑死 HFI 积分） |
| A″ | 算法绑死配置 | `observer/` 六个 `.c` 全部 `#include "motor_params_m1.h"`（3435 行） |
| Sel | 电流环身兼选择器 + 实现 | `hfi_smo_hand_step` **702** 行、`hfi_pub_step`、速度阴影 PI 住在 service 文件里。只搬函数、不立选择层，还会长回来 |
| Ops | 设计缺口 | C 代码 **0** 处 `observer_ops_t` |

### 3.2 无感其实还不是「角度源」

三个 EMF `update` **都吃 `theta_enc`**：

```c
emf_smo_update(..., float theta_enc, float omega_mech_rpm);
emf_veq_update(..., float theta_enc, float omega_mech_rpm);
emf_pll_update(..., float theta_enc, float dt);
```

头文件自书「有感旁路…不进 Park」。`theta_enc` 用于 `theta_err`、首拍把 hat 种成编码器。  
**因此当前 SMO/VEQ/PLL 是挂在编码器上的对照观测器，不是产品态无感角。**  
I/F 路径里 `obs_soft_switch` 可以把 Park 切到 θ̂，那是编排在用 hat，算法入口仍依赖编码器对照。

HFI 同样：`on_angle(theta_enc_el)`，开环/踢极性/部分 Park 回退仍用编码器。GATE 编到 **141**，本质是实验配方，不是观测器驱动。v3.0 的单次 `update(self, ia, ib, ua, ub)` **既容不下** inj/override，**也容不下** 被 Park 隔开的两相位，见 §6.3。

### 3.3 工程卫生（可先于接口拍板动手）

| ID | 问题 | 说明 |
|----|------|------|
| B | 编译期配置爆炸 | `hfi_sqwave.c` **699** 条 `#if/#ifndef`；`motor_current.c` 中 `M1_HFI_` **586** 次。切实验 = 改 `M1_HFI_GATE` + 全量重编 |

- 20 kHz 是否超 cycle（建设/WCET 的活）。

## 4. 动手前必须主人拍板的设计题

不定这三题，F4/F5 **冻不住**。

### 4.1 `theta_enc` 进不进 `observer_ops_t::update`

v3.0 签名是 `(self, ia, ib, ua, ub)`，没有 `theta_enc`。

| 选项 | 含义 | 代价 |
|------|------|------|
| **允许（对照端口）** | 另加可选参数或并行 debug 口；纯无感传约定无效值（不进误差、不播种） | 观测器里仍要写「有/无编码器」两支；要纪律保证 Park 不用这条 |
| **不允许（产品 ops）** | 观测器只吃 i/u。编码器对照走独立记录通道，不进 `update` | 旁路验证从算法对象上拆走；现有 `theta_err` 遥测要改接线 |

### 4.2 交接模块：几个、叫什么

`obs_soft_switch` **已经是** ENC/I-F → EMF-PLL 的交接层。  
**禁止**再出现第三个「只交接一段」的模块（HFI↔SMO 再单开一个 `obs_handoff`，以后 I/F 又一个）。

| 选项 | 含义 |
|------|------|
| **并进选择器** | 一个 Composite 内部容纳 ENC→PLL 与 HFI→SMO 两套门限；`obs_soft_switch` 降为 Composite 的一种策略，而不是并列模块 |
| **本轮只并语义、文件可暂分** | 对外仍只有一个选择器入口；内部文件可以先分 `.c`，但 tick / MotorCore **只看见一个 observer** |

并进时内部按 v3.0 §二十二.2：**新增策略 = 新增 `.c` + 宏/profile**，不要把 ENC 融合（带 α）和 HFI↔SMO 角交接写成一坨串行 `if`，否则 Composite 会变成第二个 `motor_current_tick`。两套是不同语义：融合 vs 交接。

### 4.3 selector 形态（新增，不定则 F4/F5 两套「都合规」）

v3.0 §4.4 MotorCore **只有一个** `observer` 槽位。多源交接有两种写法：

| 选项 | tick 看见什么 | 风险 |
|------|----------------|------|
| **① Composite（推荐）** | tick 只挂 **一个** observer 对象；init 后指针冻结；内部按策略表选源 | 符合 §4.4。该对象必须暴露 **两个相位**（§6.3），不是一次 `update`  internally 连打两拍 |
| **② tick 内分派** | tick 问 N 个源再 `if` 选角 | 等于把 `#if` 换成运行期 `if`，选择器仍长在 `motor_current.c`，F4 失败 |

**本规划默认按 ① 冻结**，除非主人改选 ②。① **不**等于「对外仍一次 `update`」。

## 6. 冻结清单（写进评审）

冻 **C 接口**（2026-10-05 起生效），不冻 GATE 数字、不冻 PI 参数。

1. 观测器 ops：**两相位**（§6.3）+ `get_theta` / `get_omega` / `is_converged` / `reset`；是否带 `theta_enc` 由 §4.1 定。v3.0 单次 `update(ia,ib,ua,ub)` 不够 HFI，不能当冻结终态照抄。  
2. 选择器：**一个**对外对象（Composite）。MotorCore 仍只挂这一个 observer。`obs_soft_switch` 不得作为与 Composite 并列的第二套 tick 交接。  
3. 电流环对无感只允许：该对象的相位 1 / `get_theta` / Park / 相位 2，以及独立 inj 槽位。  
4. 编码器 L1 API 与 `board_encoder_m1`：**维持现有冻结**。  
5. `hfi_sqwave.h` 访问器：冻结后只减不增；遥测改为读快照结构。

### 6.3 HFI 两相位与 inj 槽位（冻结时必须写死）

#### 两相位：单次 `update` 做不到 F7 等价

现行 tick（3465 → 3466 → 3661 → 3662 → 3668）：相位 1 出本拍 `theta_park`，电流环做 sincos+Park，相位 2 **吃本拍 id/iq**（`hfi_demod_step(id, iq, …)`）。  
两拍被电流环 Park 数学隔开。v3.0 §4.4 的次序是 `observer->update(ia,ib,ua,ub)` **再** `clarke_park`，HFI 解调需要的是 Park **之后**的 dq，方向相反。

| 做法 | 结果 |
|------|------|
| 两拍塞进一次 `update` | `on_current` 只能吃 **上一拍** id/iq → 一拍延迟 → 金样必偏，F7 判失败 |
| 把 Park 搬进 observer | 电流环数学进观测器，方向反了，**禁止** |
| **(a) ops 分两相位（推荐、本轮默认）** | 例如 `on_pre_park(theta_enc, dt)`（或保留 `on_angle` 语义）→ `get_theta` → 电流环 Park → `on_post_park(id, iq, iα, iβ)`。Composite **对外也持这两个相位**。SMO/编码器：相位 2 可为空操作或只做不依赖本拍 dq 的更新 |
| (b) 电流环继续点名 `hfi_sqwave_on_angle/on_current` | F5 失败 |

**删掉**任何「Composite 对外仍一次 `update`、内部消化两拍」的写法。

#### inj / override：独立槽位，不塞回 observer 表

HFI 还要 `override_voltage` / `get_inj` 改 PWM。v3.0 `update` **没有**电压输出语义。  
v3.0 §4.4 里 **deadband / ff / cmd_proc** 标了 `/* 可为 NULL */`，**observer 没有**标可为 NULL。因此 inj 只能是 **observer 之外的独立槽位**（与 deadband 同类），不能做成 observer 表上的可选函数。

| 选项 | 做法 |
|------|------|
| **A（推荐）** | 角度走两相位 observer；`hfi_inj_ops_t`（或同名）为 MotorCore 第二槽，非 HFI 为 NULL |
| **B** | 把 `get_inj` / `override` 塞进 observer 表 | 所有观测器假装会注入；且 observer 在总则里不是 NULL 槽 |
| **C** | 电流环继续认识 `hfi_sqwave_*` | F5 失败，禁止作为冻结项 |

**本规划默认：两相位 (a) + inj A。** 电流环不 `#include` HFI 私头，只认 Composite 的两相位 + 可选 inj 槽。
